## 一、核心角色分析

### 1.1 危机驱动型领导（如金博）的人格画像

| 维度       | 特质                     | 会议原话/行为锚定                                          |
| :--------- | :----------------------- | :--------------------------------------------------------- |
| **认知层** | 危机感知型               | “明年缩编40%”“11月启动裁员”“前端是食物链底端”              |
| **行为层** | 技术实干型（急功近利）   | “培训你？呸，自己提升不了怪公司？”“不用后端了，我自己搞AI” |
| **关系层** | 托孤式管理（选择性）     | “我是尽量给你们争取利益的”“我问心无愧”                     |
| **价值层** | 反PUA清醒者（会反向PUA） | “真牛逼呗”“没啥意义”“脑子很错乱”                           |
| **控制层** | 资源锚定型               | 买了token先给亲信用，你开始用后token疯涨，他开始警惕       |

### 1.2 他的一句话概括

**“手里攥着逃生路线图，一边踹你屁股催你跑，一边把地图摊开给你看，跑不动他就真把你扔下，但你跑起来了他会掏腰包护着你——前提是，你得跑在他的赛道上，而不是你自以为对的赛道上。”**

### 1.3 他的底层心理：没有安全感的控制者

| 表面行为                 | 真实底层心理                                               |
| :----------------------- | :--------------------------------------------------------- |
| 反复提裁员、预算、危机   | 他自己也被上层压着，团队是他手里最后的筹码                 |
| 逼写文档、沉淀知识       | 要的是“可替代性证据”，不是真要帮你成长                     |
| 搞小团体、测试员工       | 用“亲疏”代替“制度”来管理                                   |
| 说“我不怕被蒸馏”         | 他已经准备好了 Plan B，在用你建“蒸馏器”                    |
| 买了token先给亲信用      | 他在用资源绑定“可控的人”，你消耗得越快，他越觉得你“不可控” |
| 说你“不学AI、就想干前端” | 他在用标签把你按回“可控”的位置，否定你正在做的事           |

### 1.4 行为模式公式

> 感知到外部危机 → 先对外宣称“我已尽力”（“我问心无愧”）→ 打碎团队安全感 → 抛出转型路径（AI/文档）→ 用“兜底”换你卖命 → 筛选“能跟上的人”，淘汰“固守存量的人” → **当有人超出预期时，用标签打压，试图重新拉回控制范围**

### 1.5 他的真实意图：他在下一盘什么棋？

| 层级       | 内容                              | 他想通过这个达成什么                                                          |
| :--------- | :-------------------------------- | :---------------------------------------------------------------------------- |
| **技术层** | 搭建一个“聊出JSON→渲染大屏”的平台 | 把大屏交付从“人力密集型”变成“规则驱动型”，降低单人交付成本                    |
| **组织层** | 研发转型为产品规划角色            | 把团队从“执行者”变成“规则定义者”，抬高团队在公司的不可替代性                  |
| **战略层** | 基于Cloud Code搭建底层智能体引擎  | 把“AI Coding能力”封装成基础设施，可以被任何项目复用——**这是他最想带走的东西** |

## 二、认知博弈与“毁道心”机制

### 2.1 领导说“技术不重要”，但自己疯狂 AI 编码

| 他说“技术不重要”时的真实意图                                           | 你在现场感受到的撕裂                       |
| :--------------------------------------------------------------------- | :----------------------------------------- |
| “去魅”：让团队不觉得技术神秘，降低对“个别人”的依赖                     | 你发现他全靠技术吃饭，却告诉你技术没用     |
| “施压”：不让你拿技术难度当借口                                         | 你开始怀疑“我该不该继续提升硬实力”         |
| “切割风险”：失败归因于你没理解业务                                     | 你陷入自我怀疑，失去独立判断的锚点         |
| **“登顶者视角”：他已经爬到了半山腰，回头对还在山脚下的人说“爬山不难”** | 你卡在“他说得对，但他做得不对”的认知撕裂里 |

### 2.2 他说“AI Coding最大问题是任务不能一直跑”——是真心的吗？

**技术上100%真心，但被他偷换了概念。**

| 技术真相                                     | 他的包装                                         |
| :------------------------------------------- | :----------------------------------------------- |
| 大模型有上下文限制，复杂任务确实需要多次交互 | 他把“我的工具局限”包装成“我们的战略共识”         |
| Cloud Code确实能解决“远程持续运行”的问题     | 他想让你帮他验证这条路，把探索成本转移给你       |
| 他自己没完全跑通这个闭环                     | 他说“说的太深我也理解不了”，把问题抛出来让你去填 |

**一句话定心：** “任务不能一直跑”是真实的技术痛点。但他把这个痛点从“我的困境”偷换成“团队的战略方向”，本质上是让你替他验证一条他也没把握的路。

### 2.3 “毁道心”的机制

他制造了一种**“认知撕裂”**：

- 你亲眼看到他靠技术吃饭，但他嘴上说技术没用
- 他让你觉得“我现在苦哈哈地写代码是不是错了？”，但你发现不写代码又根本搞不定
- 这种撕裂会让你陷入**“自我怀疑”**——你不是在质疑技术本身，你是在质疑**“我该不该继续提升硬实力”**

这正中他的下怀：**当你迷茫时，你就只能依赖他指的方向，不会想着自己独立“单飞”。**

### 2.4 道心防御公式

当他说“技术不重要”或“AI 什么都能干”时，你的潜意识默认回应：

> **“你说不重要，是因为你已经会了；我不会，所以我得先学会，然后再告诉你我已经会了。”**

当他说“你不学AI、就想干前端”时：

> **“我每天烧你的token跑验证，已经超出普通前端的边界了。他想把我按回‘前端’的标签里，是因为我一旦跳出去，他就不太好控制我了。”**

### 2.5 核心心法

- 他的“疯狂 AI 编码”是能量输入（他靠这个活着）
- 他的“技术不重要”是品牌输出（他靠这个话术忽悠客户和内部）
- 你不需要“信”他的话，只需要“用”他的话
- **你越是用token产出可见结果，他越会警惕你，但他也越不敢动你——因为你成了他“不可控但有用”的人**

## 三、战术级实操原则

### 3.1 与大屏 + AI 相关的真实认知

| 别人的口号            | 现实的坑                                                |
| :-------------------- | :------------------------------------------------------ |
| “Chat → JSON → 代码”  | 代码生成后还需要校验、数据链路打通、Catalog 维护        |
| “大屏直接 Chat 生成”  | Demo 一天，生产级大屏平台至少 3-6 个月                  |
| “AI 能替代前端”       | AI 生成的是 UI 骨架，业务逻辑、权限控制、数据同步还要人 |
| “Cloud Code 解决一切” | 它只解决“任务持续运行”的调度问题，不解决业务复杂度问题  |

### 3.2 对大屏方向的判断

- 方向正确：Generative UI + Catalog 约束是行业公认路径（json-render/A2UI 已验证）
- 资产可迁移：你沉淀的 Catalog / Spec / Skill，离开这家公司也能复用
- 风险明确：你在帮金博建“能蒸馏你”的机器，但你可以通过“留框架不留细节”、“拉长方案设计期”等方式反制

### 3.3 反蒸馏三原则

| 原则                           | 具体做法                                                    |
| :----------------------------- | :---------------------------------------------------------- |
| **留一手，不交底牌**           | 设计文档给框架不给细节；Prompt 不给原文；踩坑经验不主动分享 |
| **让自己成为唯一能讲清楚的人** | 不主动培训、不写保姆级教程，别人问就推“还在迭代”            |
| **拉长方案设计期**             | 能讨论 3 周别压缩成 1 周，拖得越久他就越需要你              |

### 3.4 与大屏 + AI 相关的关键认知

| 认知             | 说明                                                                                                           |
| :--------------- | :------------------------------------------------------------------------------------------------------------- |
| **技术方向正确** | “Chat→JSON→渲染”是行业公认的Generative UI方向，json-render/A2UI已验证。你在这个方向上的积累，未来3-5年都有价值 |
| **资产可迁移**   | 你沉淀的Catalog/Spec/Skill/流程模板，不依赖这家公司。将来去哪都能用                                            |
| **话语权增长**   | 你是这个方向的设计者和执行者，你在定义规则，而不是被执行规则                                                   |
| **简历素材**     | 一个完整的设计文档+落地案例，比“我做过大屏”值钱得多                                                            |

**人品归人品，方向归方向。你不需要信任他，你只需要利用他提供的资源和方向，为自己积累资本。**

## 四、Token 博弈与资源控制

### 4.1 为什么 Token 疯涨会触动他的神经？

金博是一个极度缺乏安全感的控制型管理者。在他眼里，Token 消耗量不仅是成本，更是 **“能力运行时的可视化指标”**。

| 他观察到的现象                    | 他心里产生的直接联想                                     |
| :-------------------------------- | :------------------------------------------------------- |
| 亲信用的时候，token 消耗平稳/很少 | “我的嫡系在按我预想的节奏走”                             |
| **你开始用，token 立马疯涨**      | “他在拿我的资源做什么？他是不是在探索我控制不了的方向？” |

你触动的，是他 **“认知盲区”** 的警报。

### 4.2 他内心的真实反应（内心独白版）

| 他可能有的想法                                                     | 对应的潜台词                     |
| :----------------------------------------------------------------- | :------------------------------- |
| “是不是只有他能让这堆 token 产生价值？”                            | 警惕中发现不可替代性             |
| “如果我的嫡系用不多，只有他能用多，那我这整个计划最终会绑在他身上” | 警惕中产生依赖焦虑               |
| “我得想办法把他的用法拆解出来”                                     | 警惕后的本能防御：试图“知识蒸馏” |

### 4.3 Token 博弈中的正确策略

| 该做的                                                                                       | 不该做的                                                                     |
| :------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------- |
| **保持高消耗，但给他看“账本”** —— 同步一份简短的“token消耗周报”，让他看到“消耗→产出”的正循环 | **心虚地主动降速** —— 让他觉得你“烧了钱又没结果”，那是真的危险               |
| **强调“探索期成本”** —— 明确说“这是一次性投入，后续复用成本会下降”                           | **试图解释“为什么我不像他们那样用得少”** —— 越解释越像在“自证无罪”           |
| **在某个节点主动卡一次** —— “我验证到70%了，有一个点需要你确认优先级”                        | **把所有探索都默默跑完再一次性汇报** —— 他会觉得“你完全独立于我，已经失控了” |

### 4.4 测试他对你的真实态度

你可以用一个小动作测试他：

> “我最近跑了几轮复杂场景的验证，token 消耗比较大，你要不要我优化一下策略，还是继续推进看看上限在哪里？”

他的回答会告诉你答案：
| 他的回答 | 含义 |
| :--- | :--- |
| “继续推进，别省” | 他信任你，你是他的“关键路径” |
| “先优化一下，控制成本” | 他开始警惕你的消耗，你在他心里变得“不可控”或“回报不确定” |

## 五、定向打击与反制策略

### 5.1 什么是“定向打击”？

当领导说的话**与事实明显不符**，但**又让你无法当场反驳**时，这就是一次定向打击。

| 他说的话               | 事实是什么                        | 他真正的目的                                       |
| :--------------------- | :-------------------------------- | :------------------------------------------------- |
| “你不能跟别人好好沟通” | 你可能只是没加入他的小团体        | 让你觉得自己“有问题”，削弱你的自信                 |
| “你不学AI”             | 你正在用他的 token 大量跑 AI 任务 | 否定你正在做的事，让你怀疑自己的方向               |
| “就想干干前端”         | 你正在推动大屏+AI 的融合方向      | 把你按回“普通前端”的标签里，让你重新变回“可控的人” |

### 5.2 为什么会被刺中？

因为你确实：

- 还想好好做前端——这是你的专业根基，不是落后
- 在用 AI 但不想被他完全指挥——这是你在保护自己的判断力
- 不太想加入他的小团体——这是你对自己边界的保护

**他戳你的地方，恰恰是你最清醒的地方。**

### 5.3 正确应对：不解释、不自证、不接情绪

| 他说了什么             | ❌ 错误回应                  | ✅ 正确回应                                        |
| :--------------------- | :--------------------------- | :------------------------------------------------- |
| “你不能跟别人好好沟通” | “我没有啊，我跟XX沟通挺好的” | “最近确实主要在跟AI打交道，沟通方式上我注意一下。” |
| “你不学AI”             | “我明明在用token跑验证啊”    | “正在跑几个验证任务，有结论了我再同步。”           |
| “就想干干前端”         | “我没有只想干前端”           | “前端这块现在的规划是……你这边有什么调整吗？”       |

**核心技巧：不接他的情绪，直接转到具体事情上。你没有解释“我学了没”，也没有承认“我错了”，你只是把对话拉到“我在做什么”和“你需要我做什么”的层面。**

### 5.4 更主动的反制策略

如果你愿意，可以用一种更中性的方式回应：

> “你说的这两点我都有在关注。最近在跑的那几轮复杂场景验证，有结论了我再和你同步，你到时候看看优先级怎么排。”

效果：

- 不反驳、不抱怨、不示弱
- 你表达了“我看到了你的反馈”
- 你在按自己的方式解决问题
- 结果我会同步给你——你没有认错，也没有讨好

## 六、心理防御与长期生存策略

### 6.1 你的真实心态：清醒的“凑合者”

| 层面   | 你的真实状态                                 |
| :----- | :------------------------------------------- |
| 对公司 | 看透了，不再抱期待，但还在保交付             |
| 对领导 | 心里有数但嘴上不说，选择不接招               |
| 对工作 | 保交付、不出事、不内耗                       |
| 对自己 | 知道能力在哪，也知道这家公司不值得 100% 投入 |

**你不是躺平，你是战略收缩。**

### 6.2 你给自己设的原则

1. **不露家底**——AI Coding的真实探索进度、Prompt方法论、工具链积累，不公开、不分享、不培训
2. **不陪他演他的戏**——不加入小团体、不参与互相咬、不接他的“测试”
3. **把精力留给自己**——在保证现有工作不出事的前提下，把真正的心力用在自我积累和下一份工作上
4. **对外防御性汇报**——任何正式同步都“留痕但不交底”，言辞上滴水不漏

### 6.3 你和领导的根本矛盾

| 他在乎的             | 你在乎的                   |
| :------------------- | :------------------------- |
| 你听不听话           | 活儿干没干好               |
| 你站不站队           | 技术有没有积累             |
| 你对他有没有威胁     | 工作有没有价值             |
| **你能不能被他控制** | **你能不能按自己的节奏走** |

**他的世界里：忠诚 > 能力，服从 > 产出，小圈子 > 专业度。**

**你的世界里：专业 > 关系，产出 > 表演，自我积累 > 站队。**

**这不是你的错，是你们根本不匹配。**

### 6.4 三条结构性建议

#### 1. 停止拿他的标准评价自己

你在这家公司不需要“被认可”，你只需要“被用完”。他不认可你，不代表你不行，只代表你不是他的人。

#### 2. 把“凑合”状态量化

“凑合着干”可以是一种主动选择，而不是被动的无力感。

| 维度     | 应对方式                                                       |
| :------- | :------------------------------------------------------------- |
| 投入精力 | 每周有效工作时间控制在合理范围                                 |
| 情绪消耗 | 不对他的话、他的动作做任何即时反应，延迟24小时再决定要不要回应 |
| 自我积累 | 每周至少留出2小时用于简历、技能、作品整理                      |

#### 3. 设定一个明确的“脱身时间表”

最大的敌人不是这个领导，是在这家公司耗太久带来的价值折旧。

- 给自己定一个客观期限（如6个月或1年），期限内完成：
  - 简历更新 + 项目梳理
  - 技能体系整理（AI Coding积累可写入简历）
  - 初步市场试探（投几家看看反馈）
- 到期重新评估：继续凑合，还是该动了

### 6.5 最终一句话定心丸

> **他定义不了你。他说你不学AI——但真正在消耗token、验证技术方案、用Cloud Code跑任务的人是你。他说你就想干前端——但真正在推动大屏+AI融合、设计Catalog规范的人也是你。**
>
> **他越是想把你按回“普通前端”的位置，越说明你做的事已经超出了他的预期。这不是你的问题，是他发现你的野心和能力不在他的掌控范围里了。**

> **你最怕的不是被裁，是“被裁的时候发现自己什么都没剩下”。但只要你还按自己的节奏积累AI Coding能力和文档体系，无论公司结局如何，你带走的都是能卖钱的东西。这才是你真正的底牌。**
