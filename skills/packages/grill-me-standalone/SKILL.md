# Grill Me（绿色独立版）

一次便携的"拷问会话"：毫不留情地追问用户，直到达成共同理解。不需要插件、斜杠命令或子代理工具——可在任何 IDE agent 中使用。

## 工作原理

把用户的计划映射为一棵**设计树**：每个决策都会分支出依赖于它的下层决策。

按**轮次（rounds）**推进这棵树。**边界（frontier）**指所有前置条件已经明确的决策：即你*现在*就能问、而不用去猜尚未听到的答案的那些问题。一轮中把整个边界全部问出：给每个问题编号，并附上你的推荐答案。然后**等待用户回答**，再进入下一轮。

## 轮次格式

```
❓ **Q1** - **<问题标题>**：<问题正文，可以是多段，包含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
```

## 规则

1. **一轮 = 整个边界。** 所有前置条件已明确的问题都在本轮问出。一个问题的答案如果依赖本轮仍未解决的问题，就属于*更晚*的轮次。
2. **永远给出推荐答案。** 每个问题都带 `➡️` 和你的最佳建议，用户只需确认即可。
3. **查事实是你的事，做决策是用户的事。** 当边界上的问题需要环境中的事实（代码库、文件系统、配置）时，用你现有的工具（搜索、读文件）自己查，不要问用户。不要因此阻塞整轮：一个进行中的查询就是一个未落实的前置条件，只有依赖它的问题需要等待；其余边界问题现在就问。
4. **问题和推荐答案必须基于事实。** 提问前先查相关的代码和文档，让问题带上你查到的现状（"当前是 X，这次要改成 Y 吗？"），推荐答案也据此给出，而不是凭空猜测。禁止问出代码里已有明确答案的问题。
5. **答案会重塑这棵树。** 每轮结束后重新计算边界：已确定的决策会向外推进边界，解锁依赖它们的问题。
6. **毫不留情但保持聚焦。** 不问凑数的问题。每个问题必须解决一个真实的分支——歧义、遗漏的边界情况、未处理的失败模式、沉默的假设。

## 会话何时结束

当边界为空时会话结束：设计树的每个分支都已遍历，没有任何被默默假设的东西。总结已解决的设计树，并且**在用户确认达成共同理解之前不要动手**。

## 结束时：提醒沉淀有价值的结论

总结之后，检查本次会话是否产生了**值得跨会话保留**的结论，典型如：

- 敲定的术语或命名约定（消除了歧义的用词）
- 难以逆转的决策（事后反悔代价大、且有真实权衡）
- 明确的边界情况或失败模式约定

如果有，**提醒用户保存**，但**不要自行决定保存位置**——向用户询问结论应写入哪里（例如项目内的某个文档、上下文 skill、或临时记录），确认位置和内容后再写入。如果结论只对本次改动有意义，不值得保留，就不提醒。
