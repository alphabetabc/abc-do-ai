# memo · 接口复用的前提疑虑（2026-10-09）

## 背景

深圳保障屏是**新的页面、新的业务能力**，但 004-01 迁移中大量接口直接复用了信管局 viewPageId/viewItemId（`open-close-ceremonies-view` 下各 viewItemId）。

## 疑虑

- UI 复用、数据结构复用都说得通；但**在服务端没有明确说明"业务能力一致"的前提下，接口标识也被复用**，这是有问题的。
- 新页面/新能力，服务端即使维护配置/表，也应当维护在**新的配置或新表**里；直接沿用旧标识，存在读到信管局旧数据（或读到空）的风险。
- 当前前端代码实际上是按"标识照抄、数据由服务端按深圳屏配置出数"的假设在写（如顶部统计栏三-1 的字典确认就是这个模式），但这个假设对其他复用接口**未逐一确认**。

## 结论

- 该疑虑用户已知晓，暂不登记 004-00（用户判断服务端沟通意义有限）。
- 如后续服务端明确了"配置化出数 / 新表隔离"的机制，或反过来确认数据同源，请回填本 memo。
