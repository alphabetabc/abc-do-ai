# 大屏数据问题经验沉淀（task-074 派生）

> 来源：task-2026-09-02-074 各模块无数据展示（074-001~004，覆盖 038/039/040/041 四屏约 15 项修复）。
> 定位：**跨项目可复用**的检查清单 + 架构约束 + spec 必填项 + 排查剧本。
> 核心思想：这些 bug 几乎全部**不报错**（空集 / 0 / 撞色 / 占位文本），只有清单和模板能防住，文档只解决「知道」。

## 1. 检查清单（新大屏联调前逐项打勾）

### 数据接入前

- [ ] **码表口径核对**：库表主键码长（CANT_CODE 9 位 / ORGAN_ID 6/9 位 / abi 4 位） vs 前端地图 adcode（6 位）。禁止直接 `==` 比较，统一前缀匹配或入库归一化（074-002/003/004 反复出现，最顽固）
- [ ] **行数对账**：PM 源数据行数 vs 本地验证库行数（074-001：letter_screen_1 268 vs 992）

### 快照 / 时序表

- [ ] 时间过滤粒度（按天 / 按秒）必须明确写入 spec，**实现者不得自行决定**（074-003 trend 漏省级行：同日多时间戳，`STATS_DATE = MAX(...)` 精确到秒静默排除 23:00:00 行）
- [ ] 验证 SQL 必须覆盖「同一天多个时间戳」场景

### 图表复用

- [ ] 复用组件前核对：Y 轴量级（万 / 件 / 个）、单位文案（039/040 柱图照抄 038 人口大屏的 /10000，信访数据件级 → Y 轴全 0）
- [ ] 色板数量 ≥ 类目数（039/040 demands：PIE_COLORS 8 色 vs 9 类目，第 9 项与第 1 项撞色）

### 前后端联调

- [ ] 占位符清零：grep `身份\d|TODO|FIXME|mock`（039/040 身份类型横轴「身份N」硬编码）
- [ ] 「无数据」必须先区分：**数据缺失 vs 代码过滤掉了**——各跑一次裸 SQL（去掉所有 WHERE 时间/码长条件）确认库里有数

## 2. 架构约束（防止问题再生）

- **同构大屏禁止整目录拷贝**：仅差少量参数（如 REG_AUTHORITY='1'/'2'）的模块必须参数化抽公共 service/SQL。040 是 039 修复前代码的独立拷贝，039 的修复一个都没传播过去，四类问题原样存在，074-004 全部重修一遍
- 沈抚新区合并这类「码映射」规则要写成**前缀匹配**（CANT_CODE 前 4 位 `2115`），并仅作用于市级汇总行（余位全 0 判断），避免误伤下钻行

## 3. spec 模板必填项（约束 PM 输入，堵住唯一硬缺口）

每个数据源增加「数据快照」字段，评审时一眼看出未答：

```markdown
## 数据快照（每个数据源必填）
- 快照粒度：天 / 小时 / 秒
- 多快照并存时取哪条：MAX(时间) / 指定日期 / 全部聚合
```

其余 PM 输入质量整体良好（卡片取值公式、下钻规则、字段映射、I-9 答复都清晰）；真正缺口仅两处：快照口径（O-14 长期开放）+ GB_JXGB「军休 vs 离休」语义（O-19 未答复）。

## 4. 排查剧本（「大屏无数据」固定顺序）

1. **跑裸 SQL**：确认库里有数（区分数据缺失 vs 代码过滤）
2. **查代码过滤条件**：码长比较 / 时间粒度 / REG_AUTHORITY / ORGAN_ID
3. **查前端渲染**：单位换算 / 中文名映射 / 色板数量 / 占位符

## 5. 归因纪律（复盘时自检）

- 复用组件出 bug ≠ 跨业务没核对（动机推断，无证据不写）
- 引用「PM 未提供」前必须回溯 PM 原文核对（074 复盘曾把 channels 口径误归 PM，实际 PM 输入 §4.1/4.6 有渠道映射）
- 同族问题 ≠ 同一根因（041 的问题是码长 + GROUP BY 缺失，不是拷贝不同步）
