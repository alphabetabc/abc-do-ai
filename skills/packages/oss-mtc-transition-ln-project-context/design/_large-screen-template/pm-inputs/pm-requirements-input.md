# 产品经理需求输入（非研发表述）

> **用途**：产品同学用业务语言填写本页；将填写后的全文（或粘贴到对话里）交给 AI，按本仓库 `docs/specs/_template` 与同目录各 artefact 的约定，生成新特性目录下的 `spec.md`、`plan.md`、`tasks.md`、`data-model-extensions.md`、`acceptance-tests.md`。  
> **原则**：只写「要什么、给谁用、怎样算对」；表名、字段、HTTP、OpenAPI 可写「已知则填、未知则标待确认」，由研发/AI 回填 design 索引与契约占位。  
> **参考成品**：[`../005-contrast-information/`](../005-contrast-information/spec.md)（多页表格 + 导入导出 + 动态列示例）。  
> **填写示例**（反推样例）：[`pm-requirements-input-example.md`](./pm-requirements-input-example.md)

## K. 静态资源与附件（可选）

> **是否一定要建 `assets`？** 不强制。只有当你希望 **切图、导出的 PDF、流程图源文件等随仓库版本管理**、且 AI/研发能在 PR 里一并评审时，再入库到下方路径。

### 推荐目录

| 场景 | 放置位置 | Markdown 引用示例（按文件所在目录调整） |
|------|----------|------------------------------------------|
| **某个特性专用**（主推荐） | 与该特性 `spec.md` 同级：`docs/specs/<编号-短名>/assets/` | `![工具栏示意](./assets/contrast-toolbar.png)` |
| **仅服务于 PM 模板/培训示例** | `docs/specs/_template/assets/` | 见 [\_template/assets/README.md](./assets/README.md) |
| **仍为外链、不入库** | 无 | 在 §J 写完整 URL；正文可用 `[说明文字](https://...)` |

### 命名与格式建议

- 文件名用小写英文与短横线，避免空格与中文路径（跨平台与 AI 解析更稳）。
- 图片优先 `png` / `webp` / `svg`；复杂产品说明可用 `pdf`。体积很大时团队可改用 Git LFS 或仅存链接。

### 与 AI 协作

- **尚无 pm-input、仅有 assets**：按 [ai-prompts-guide.md §1.3](../../../ai-prompts-guide.md#13-从-assets-生成-pm-requirements-inputagent-模式) 生成本文件，供产品审阅。
- **pm-input 已定稿、要生成 spec**：按 guide §2；对话中 `@` 本文件与 `assets/`，生成 `spec.md` 时附录保留相同相对路径引用。
