## B. 背景与范围

### B.1 当前痛点

1. 需要基于一份名单，同时核对人员在档案里是否存在，以及多条业务条线（人口、社保、医保等）上的比对结论。
2. 不同业务同事关心的条线不同，希望先选定「要比对哪些类别」，再出表，避免一进来就是上百列。
3. 核实结果经常要发给协作方或留档，需要与页面上看到的列一致的 Excel 导出，以及标准导入模板减少格式纠纷。

### B.2 本期目标

上线「对比信息」页面：支持选择比对类别、下载模板、导入姓名与身份证号、表格分页查看、按当前表格全部导出；未选类别时仍有「在不在档」等基础信息；选类别后表格动态加列，带子类别时用多层表头展示。

### B.3 明确不做（范围外）

| 内容 | 说明 |
|------|------|
| 比对任务调度、后台往比对结果里灌数的流水线 | 归属数据工程/管道；本功能只使用已有数据 |
| 与「按月汇总统计」同一套报表口径 | 统计类走「比对统计查询」等专项；本页是**按导入名单的明细** |

## D. 核心用户旅程

1. 用户从菜单进入「对比信息」，看到上方操作区和下方空表格（或上次会话约定，由产品定）；操作区至少有：**选择查询类别**、**导入**、**全部导出**、**下载模板**。
2. 用户可先**下载模板**，在本地填好**姓名**、**身份证号**两列，再点**导入**上传；成功后表格出现对应行，展示序号、姓名、身份证号和**存在状态**（在档相关口径见数据说明）。
3. 若用户**尚未选择查询类别**，表格只有上述「基础列」，不出现各比对条线维度的扩展列。
4. 用户点击**选择查询类别**，弹出窗口，左侧为可选类别、右侧为已选，支持搜索与移入移出；点**确定**后，表格在基础列右侧**按所选类别增加列**。
5. 若用户选的是带子类的父类（如「社保信息」），表头为**复合表头**：父类下挂子类，子类下再挂具体比对项列，具体层级与产品稿、业务字典一致。
6. 用户通过底部分页切换页码、每页条数；比对结果格子若无数据，显示为空或统一占位符（如「—」）。
7. 用户点**全部导出**，得到 Excel，**列集合与顺序与当前页面表格一致**（含动态出来的列）。

> 本页**无 §E.1 筛选条件表**（名单由导入驱动，非页内 Input 筛选）；操作见 §E.1 页面按钮。

**关键分支**

- **未选类别**：仅基础列（序号、姓名、身份证号、存在状态）。
- **勾选父类别**：等价于要把该父节点下**整棵子树**里所有「叶子比对项」都查出来、展示出来（例如社保下企业养老、城居养老、就业登记等多组子列）。

## E. 界面清单

### E.1 查询区与工具栏

> 本特性**无页内筛选条件**（名单由导入驱动）；以下仅列页面按钮。列表/查询类功能见模板 [`pm-requirements-input.md`](./pm-requirements-input.md) §E.1「筛选条件」表。

#### 页面按钮

| 中文名 | 点击后发生什么（一句话） |
|--------|---------------------------|
| 选择查询类别 | 打开弹窗，穿梭框选择要比对的业务类别，搜索/移入移出后确定，表格按选择扩展列。 |
| 导入 | 选择本地 Excel 上传，校验通过后名单进入当前列表并驱动查询展示。 |
| 全部导出 | 按当前表格列与数据导出 Excel。 |
| 下载模板 | 下载仅含姓名、身份证号两列的空表模板。 |

### E.2 表格 / 列表

- **固定列**（有数据即展示）：序号、姓名、身份证号、存在状态。
- **随条件变化的列**：用户确认「比对类别」后，按类别增加各比对维度列；列顺序与业务类别树或产品约定一致。
- **复合表头 / 分组**：父类别占一行分组，子类别再分组，最底层为具体比对字段列；例如「社保信息」下分企业养老保险、城居养老保险、就业登记形式等，每组下面再挂若干叶子比对项。**验收口径**：全选类别时，至少覆盖人口信息、犯罪信息、税收信息、贷款信息、社会救助信息、社保信息（含企业养老：人员缴费状态/人员类别/离退休类别；城居养老：缴费状态/待遇发放状态；就业登记形式：就业单位性质）、住房状况、医保信息、信访诉求等（与数据字典中的类别定义一致）。
- **分页**：需要；交互与常见后台表一致（每页条数、总数、跳页）。**序号**用分页内连续还是全局连续——可单独定口径。

### E.3 弹窗 / 抽屉 / 穿梭框（若有）

- **左侧**：可选的比对类别（从业务字典来，根级类别可选）。
- **右侧**：已选类别。
- **确定后**：刷新表格列定义并按新列查询展示；未确认前不改变当前列。

## F. 数据与业务规则（业务词为主）

- **主数据从哪来**：姓名、身份证号以**导入文件**为准作为本页主键展示；系统用身份证去关联档案与比对结果。
- **状态类字段**：「存在状态」表示人员在档案侧的认定结果；实现侧需与档案表字段及数据字典对齐（历史上曾用字段名 `RYSCZT`，以实际库表与 design 登记为准）。
- **指标/比对结果**：每个比对类别格子展示该人员在**该类别下「最新一次」比对记录**的结果值；若有多条同时间记录，需有稳定规则取其中一条（由研发与数据规范约定）。
- **类别树**：选父节点时，查询与列表要覆盖该父节点下**所有叶子比对类型**（例如选「社保」则其下各子项都出现）。
- **与外部系统或批任务**：本期**只读消费**已有比对结果与档案数据，不在此页面触发写入比对流水或调度任务。

（研发映射备忘，非产品必写：档案侧 `archive_infor` 与名单按身份证等关联；比对结果表按人员身份证 + 比对类型取最新值；类别树与 `comparison_type` 字典对齐。）

## G. 验收标准

| # | 标准 |
|---|------|
| S1 | 已登录且有权限的用户打开「对比信息」页，能看到工具栏：**选择查询类别**、**导入**、**全部导出**、**下载模板**。 |
| S2 | 未选择查询类别时，表格只有：**序号**、**姓名**、**身份证号**、**存在状态**。 |
| S3 | 在「比对类别」中勾选并确定后，表格按所选类别**动态增加列**；父类别带子时，表头为 **父 → 子 → 叶子比对项** 的复合结构，并与产品稿一致。 |
| S4 | **导入**只接受约定模板（姓名、身份证号）；**下载模板**与导入格式一致。 |
| S5 | **全部导出**的 Excel **列与当前页面表格一致**（含动态列）。 |
| S6 | 未登录、无权限、错误请求、服务异常时提示符合全站约定；列表加载中有加载态，无数据有空态。 |

**故事验收**（Given / When / Then）

- **场景：仅基础列**
  - Given：用户已登录有权进入页面，且已导入名单但未确认任何比对类别  
  - When：查看表格  
  - Then：仅有序号、姓名、身份证号、存在状态；无比对扩展列  

- **场景：单类扩展列**
  - Given：用户已导入名单  
  - When：在比对类别中选择「人口信息」并确定  
  - Then：在基础列外增加与人口信息相关的比对列，单元格值为该类别下最新比对结果口径  

- **场景：复合表头**
  - Given：用户已导入名单  
  - When：选择带子类的「社保信息」并确定  
  - Then：表头为复合结构，包含企业养老、城居养老、就业登记形式等分组及下属叶子列  

- **场景：模板与导出**
  - Given：用户在对比信息页  
  - When：下载模板并按模板填写后导入；再点击全部导出  
  - Then：导入成功展示行；导出列与当前表头一致  

- **场景：错误与权限**
  - Given：文件格式错误或用户无导入/导出权限  
  - Then：前端展示可读错误；与全站 HTTP/错误体约定一致

## H. 非功能与体验（可选）

- **数据量级预期**：名单与导出行数可能较大；超大时需与架构约定异步导出或条数上限，并在说明中告知用户。
- **表格很宽时**：列随类别增多会横向变宽，需保证可横向滚动；表头冻结、首列冻结等与架构及前端规范对齐，避免卡顿。
- **其它**：导入文件大小、行数上限在运维或接口约定中明确。

## I. 开放问题 / 待确认

1. 「存在状态」对应档案字段在各环境是否一致、码表含义是否已定稿，是否需合并进全库数据字典。
2. 比对记录里的「业务日期」实际存储格式不统一时，如何判断「最新一条」——需数据与研发在实现环境拍板。
3. 同一身份证对应**多条档案记录**时，存在状态以哪一条为准（需默认规则）。
4. 未导入任何人但已选了比对类别时，扩展列是保留表头还是隐藏——产品可二选一并写死。
