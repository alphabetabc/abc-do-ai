# 007 · 大屏地图与周边数据联动

> 本文件描述 4 个大屏（038 人员信息 / 039 辽宁信访 / 040 进京信访 / 041 信访比对）**地图选中 → 周边模块同步响应**的交互契约 + 数据响应层级约定。
> 这是大屏「点击地图 → 其他卡片/柱图同步响应」交互模式的单一事实来源，**覆盖全部 4 屏**。
> 存放：本目录（`oss-mtc-transition-ln-project-context/design/`）——团队私有协作区，沉淀大屏开发知识。

**本文件不记录的内容**：代码实现、接口路径、SQL 表、字段、配置项。这些见代码仓库和 `docs/design/api-contracts.md` / `docs/design/data-models.md`。

## 1. 038 人员信息大屏

### 1.1 store

- 组件目录 `personnel/`，store 字段 `currentRegion`（runtime 键 `current_region`），对象 `{ adcode: number, name, level: 'province'|'city'|'district', alias?, parentCity? }`
- **无 store 级默认值**：由地图挂载 effect 派发一次 `{ adcode: 210000, name: '辽宁省', level: 'province' }`
- **adcode 是 number 类型**（与其他屏 string 不同，§5.1）

### 1.2 地图点击行为

地图组件含**下钻栈**（`useState` + `stackRef` 镜像），初始栈底为省级。

| 用户操作     | dispatch 内容                                             | 地图显示                   | 说明                                                              |
| ------------ | --------------------------------------------------------- | -------------------------- | ----------------------------------------------------------------- | --------------------------- | ---- |
| 挂载（首次） | `{adcode: 210000, name: '辽宁省', level: 'province'}`     | 省级 14 市                 | 初始化默认                                                        |
| **双击地市** | `{adcode, name: alias                                     |                            | name, level: 'city'}`                                             | 下钻到该市（区/县 geojson） | 压栈 |
| **双击区县** | `{adcode, name, level: 'district', parentCity: 栈顶市码}` | **不下钻**（停在地市视角） | 街道级无 geojson，地图 adcode 用 parentCity                       |
| **返回**     | 弹栈后 dispatch 栈顶 region（不含 parentCity）            | 回上级                     | 通过 `onApiChange` 外露 `canGoBack / goBack` 供卡片级返回按钮调用 |

- **无单击行为**（仅双击下钻 + 返回）。
- 地图自身取数：`cantType: '4' | '6'`；**`cantType='8'`（街道级）已废弃**，district 级复用 parentCity 的区县数据。

### 1.3 周边模块订阅清单

订阅 `currentRegion`、以 `region.adcode` 为请求入参各自重拉（5 个模块）：

| 模块                                           | 请求参数                                                                                                   | district 级处理               |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------- |
| retiree-total-card（合计卡片）                 | `cantCode = String(region.adcode)`                                                                         | 无需过滤（后端按区划取数）    |
| retiree-pie-card（饼图）                       | 同上                                                                                                       | 无需过滤                      |
| employment-bar-card（柱图）                    | 同上                                                                                                       | 无需过滤                      |
| entitled-object-bar-card（柱图）               | 同上                                                                                                       | 无需过滤                      |
| **regional-population-bar-card（各地区柱图）** | `cantType = level==='province' ? '4' : '6'`；cantCode：province→'' / city→adcode / **district→parentCity** | **客户端过滤单柱**（见 §1.4） |

### 1.4 层级响应矩阵

| 模块                         | 省          | 市                | 区/县                              |
| ---------------------------- | ----------- | ----------------- | ---------------------------------- |
| retiree-total-card           | ✅ 全省合计 | ✅ 该市合计       | ✅ 该区/县合计                     |
| retiree-pie-card             | ✅ 全省分布 | ✅ 该市分布       | ✅ 该区/县分布                     |
| employment-bar-card          | ✅ 全省数据 | ✅ 该市数据       | ✅ 该区/县数据                     |
| entitled-object-bar-card     | ✅ 全省数据 | ✅ 该市数据       | ✅ 该区/县数据                     |
| regional-population-bar-card | ✅ 14 市柱  | ✅ 该市 N 区/县柱 | ✅ **1 柱（本区/县，客户端过滤）** |

### 1.5 district 级客户端过滤（各地区柱图专属）

district 级时柱图请求参数用 `parentCity`（复用上级地市的区县数据，避免后端新增接口），返回后前端过滤：

```ts
// 先用地图区划清单去脏（开发区等地图上不存在的区划）
scoped = filterDistrictsToMap(raw, (it) => it.adcode, cantCode);
// 再只留本区/县一根柱（9 位 key 与 6 位 adcode 按 slice(0,6) 对齐）
scoped.filter((it) => String(it.adcode).slice(0, 6) === String(region.adcode));
```

公共工具 `filterDistrictsToMap`（`utils/mapDistrictFilter.ts`）为地图/柱图共用。

### 1.6 空态契约

| 场景                      | 前端响应                   |
| ------------------------- | -------------------------- |
| 各模块请求返回空数组/空值 | Empty 提示                 |
| 有数据但值小（稀疏）      | 正常渲染（**区别于空态**） |

## 2. 039 辽宁信访大屏

### 2.1 store

- `petition/store.ts`，字段 `currentRegion`（runtime 键 `current_region`），对象 `{ adcode: string, name, level, parentCity? }`
- `defineFields` 写了 default 对象，但 **runtime 初始化并不消费 default**，实际默认同样靠地图挂载 `syncRegion(PROVINCE)`；消费端另有 `?? '210000'` 兜底
- adcode 为 **string** 类型

### 2.2 地图点击行为

下钻栈用 `stackRef`（useRef，**不触发重渲染**，返回按钮显隐非响应式）。dispatch 收敛为唯一封装 **`syncRegion`**（含 parentCity 条件展开；task-073 修复过手动 pick 丢弃 parentCity 的 bug）。

| 用户操作     | syncRegion 调用                                                                                     | 地图显示      |
| ------------ | --------------------------------------------------------------------------------------------------- | ------------- |
| 挂载（首次） | `syncRegion(PROVINCE)` + `fetchMap('4')`                                                            | 省级 14 市    |
| **双击地市** | `syncRegion({adcode, name, level:'city'})` + `fetchMap('6', adcode)`                                | 下钻该市区/县 |
| **双击区县** | `syncRegion({...level:'district', parentCity: 栈顶市码})`，地图**不变**                             | 保持地市视角  |
| **返回**     | 弹栈：回省 → `fetchMap('4')+syncRegion(PROVINCE)`；回地市 → 地图不变 + `syncRegion({level:'city'})` | 回上级        |

- 无单击行为；返回按钮**内嵌在地图组件内**。
- 支持 `visualMapRight` prop（visualMap 右置 + 高低文字）。

### 2.3 周边模块订阅清单（3 个）

| 模块                                  | 请求参数                                            | district 级处理                    |
| ------------------------------------- | --------------------------------------------------- | ---------------------------------- |
| identity-type（身份类型）             | `cantCode = currentRegion?.adcode ?? '210000'`      | 无需过滤                           |
| channel-stat（渠道）                  | 同上，依赖 `[currentRegion?.adcode]`                | 无需过滤                           |
| **petition-region-bar（各地区柱图）** | province→'' / city→adcode / **district→parentCity** | **客户端过滤单柱**（同 §1.5 模式） |

### 2.4 层级响应矩阵

| 模块                | 省              | 市                | 区/县                              |
| ------------------- | --------------- | ----------------- | ---------------------------------- |
| identity-type       | ✅ 全省身份分布 | ✅ 该市身份分布   | ✅ 该区/县身份分布                 |
| channel-stat        | ✅ 全省渠道分布 | ✅ 该市渠道分布   | ✅ 该区/县渠道分布                 |
| petition-region-bar | ✅ 14 市柱      | ✅ 该市 N 区/县柱 | ✅ **1 柱（本区/县，客户端过滤）** |

### 2.5 district 级客户端过滤

同 §1.5 模式：请求参数用 `parentCity`，返回后 `filterDistrictsToMap` 去脏 + `adcode.slice(0,6) === region.adcode` 过滤单柱。

### 2.6 空态契约

同 §1.6（空数组/空值 → Empty；稀疏 → 正常渲染）。

## 4. 041 信访比对大屏

### 4.1 store：两个状态变量

| 变量       | 含义                 | 默认值                 | 取值                        |
| ---------- | -------------------- | ---------------------- | --------------------------- |
| `organId`  | 当前选中的行政区划码 | `'210000'`（辽宁省级） | 4-9 位数字标准码            |
| `cantType` | 地图当前显示的层级   | `'4'`（地市列表）      | `'4'`=地市级 / `'6'`=区县级 |

> **核心约束**：只有地图模块能写这两个变量；其他模块只能读。这样保证**单一触发源**，避免多源写入引发的竞态。

`setOrganId(organId, cantType)` 是**唯一的写入入口**。一次原子写入 → 所有订阅者同时收到新值。每个周边模块订阅 `organId`（读）、并以 `organId` 作为请求入参重拉数据。订阅是声明式的，开发者**不需要手动监听变化**。

### 4.2 地图点击行为

| 用户操作                              | `setOrganId` 调用                 | 地图显示                     | 周边模块数据响应                                      |
| ------------------------------------- | --------------------------------- | ---------------------------- | ----------------------------------------------------- |
| **双击地市**（如沈阳市）              | `setOrganId('210100', '6')`       | 切到市级 → 展示该市下辖区/县 | 全部以 `organId='210100'` 重拉，柱图显示该市下辖区/县 |
| **单击区县**（如和平区）              | `setOrganId('210102', '6')`       | 保持市级视图，但高亮选中区县 | 全部以 `organId='210102'` 重拉，柱图显示该区县        |
| **再点已选区县 / 点空白（取消选中）** | `setOrganId(父级市 organId, '6')` | 回到市级常规显示             | 全部以父级市 `organId` 重拉                           |
| **返回省级**                          | `setOrganId('210000', '4')`       | 省级 14 市                   | 全部以 `'210000'` 重拉，柱图显示 14 市对比            |

> 来源：task-062 拍板的交互协议。**041 独有「单击区县」+「取消选中」行为**。

### 4.3 周边模块订阅清单（7 个）

地图一次 `setOrganId` 调用，**同时**触发以下 7 个周边模块重拉数据。每个模块独立请求、互不阻塞：

| #   | 模块                         | 数据含义                                             |
| --- | ---------------------------- | ---------------------------------------------------- |
| 1   | **trend**（12 月趋势）       | 全省/市/区/县最近 12 个月的信访量趋势                |
| 2   | **appeal**（主要诉求占比）   | 全省/市/区/县信访诉求类型分布                        |
| 3   | **rank**（各地区柱图）       | 全省 14 市 / 某市下辖区/县 / 某区/县的信访件数量对比 |
| 4   | **map**（地图热力图）        | 省级 / 市级 / 区/县级的信访密度热力图（地图自身）    |
| 5   | **summary**（3 张概要卡片）  | 全省/市/区/县的信访合计数值（3 单值合计维度）        |
| 6   | **channels**（各渠道卡片）   | 全省/市/区/县的信访渠道分布（6 数据点）              |
| 7   | **identity**（身份类型对比） | 全省/市/区/县的身份类型分布（11 指标轴）             |

**首次进入大屏**也触发一次（页面初始化时订阅触发），不依赖用户点击行为。

### 4.4 层级响应矩阵

| 模块                      | 省（`210000`）    | 市（`210100`）      | 区/县（`210102`）    | 备注                          |
| ------------------------- | ----------------- | ------------------- | -------------------- | ----------------------------- |
| **trend**（12 月趋势）    | ✅ 全省 12 月趋势 | ✅ 该市 12 月趋势   | ✅ 该区/县 12 月趋势 | 层无感                        |
| **appeal**（诉求分布）    | ✅ 全省诉求分布   | ✅ 该市诉求分布     | ✅ 该区/县诉求分布   | 层无感                        |
| **rank**（地区柱图）      | ✅ 14 市聚合      | ✅ 该市 N 区/县     | ✅ 1 行（本区/县）   | **3 层级分流**                |
| **map**（热力图）         | ✅ 14 市热力      | ✅ 该市 N 区/县热力 | ✅ 1 点高亮本区/县   | 层无感（数据已在 SQL 层聚合） |
| **summary**（3 单值合计） | ✅ 全省合计       | ✅ 该市合计         | ✅ 该区/县合计       | 层无感                        |
| **channels**（6 数据点）  | ✅ 全省渠道       | ✅ 该市渠道         | ✅ 该区/县渠道       | 层无感                        |
| **identity**（11 指标）   | ✅ 全省身份分布   | ✅ 该市身份分布     | ✅ 该区/县身份分布   | 层无感                        |

**层无感 vs 层级敏感**：

- **层无感（6 个）**：`trend / appeal / summary / channels / identity` + `map`。无论 `organId` 是哪一层，后端数据按 organId 自然过滤聚合；前端无脑展示。
- **层级敏感（1 个）**：仅 `rank` 需要按 `organId` 层级做差异化响应（§4.5）。

### 4.5 后端 organId 3 层级分流（rank 专属）

三层 organId 判别（基于 6 位标准码）：

| 层级  | 判别规则                      | 示例                      |
| ----- | ----------------------------- | ------------------------- |
| 省    | 6 位末 4 位全 0               | `'210000'`、`'2100'`      |
| 市    | 6 位末 2 位 0 但末 4 位不全 0 | `'210100'`、`'210100000'` |
| 区/县 | 6 位末 2 位非 0               | `'210102'`、`'210124'`    |

各层数据响应契约：

| organId 层级 | 期望响应                                                                  | 柱图展示            |
| ------------ | ------------------------------------------------------------------------- | ------------------- |
| 省           | 14 个市的聚合数据（双组本地+进京，每市 SUM 自辖区/县行，前 4 位前缀匹配） | 14 柱（按合计降序） |
| 市           | 该市所有区/县的原数据                                                     | N 柱（按合计降序）  |
| 区/县        | **该区/县 1 行**                                                          | 1 柱                |

**关键约束（服务端过滤）**：district 级 organId 查询时，库内数据按 city-level 组织（区/县行存在父级市的 organId 下，不在 district 自己的 organId 下），所以查询时需**先映射到父级市 organId**，再用 `CANT_CODE` 前 6 位过滤出本区/县。

### 4.6 空态契约

| organId 层级 | 空态触发条件                | 前端响应                   |
| ------------ | --------------------------- | -------------------------- |
| 省           | 双组 14 市 `num` 全 0       | `regions: []` → Empty 提示 |
| 市           | SQL 返 0 行 / 区/县全 0 NUM | `regions: []` → Empty 提示 |
| 区/县        | 父级市查询后过滤出 0 行     | `regions: []` → Empty 提示 |

> 注：「数据稀疏」≠「空态」——稀疏是数据正常但值小，空态是返回结构为 `[]` 或全 0。前端组件需在 Empty 与「有数据但值小」两种状态下给出**区分提示**。

### 5.3 district 级处理策略对比（关键差异）

| 大屏                    | 策略类型       | district 级数据如何取到？                                                 |
| ----------------------- | -------------- | ------------------------------------------------------------------------- |
| 038 personnel           | **客户端过滤** | store 携带 `parentCity`，前端用 `parentCity` 请求 + `slice(0,6)` 过滤单柱 |
| 039 petition            | **客户端过滤** | 同 038                                                                    |
| 040 beijing-petition    | **客户端过滤** | 同 038                                                                    |
| 041 petition-comparison | **服务端过滤** | 后端把 `organId` 映射到父级市查询后再按 `CANT_CODE` 前 6 位过滤           |

**两种策略对比**：

- **客户端过滤（038/039/040）**：store 携带 `parentCity`，周边模块订阅时拿到 `adcode` + `parentCity`，自己按需过滤。优点：减少请求次数；缺点：依赖 store 字段完整性（`parentCity` 必须准确携带）。
- **服务端过滤（041）**：后端把 district 级 organId 映射到父级市，再按 `CANT_CODE` 过滤。优点：前端逻辑简单；缺点：每次 district 级点击都触发 1 次父级市 SQL。

### 5.4 演进建议

- **短期**：041 单独维护（因策略差异较大，统一风险高）；039/040 逐行重复代码可先抽公共层（地图组件 + 3 订阅组件同构，仅 store 实例与 API service 不同）
- **中期**：把 4 大屏 `parentCity` 推导逻辑提到 store 工厂层（`@/components/large-screen/interaction-store/`），让 041 也用对象字段（替换现有 `organId` 字符串）；统一 adcode 类型为 string（038 的 number 与消费端 `String()` 转换散落各处）
- **长期**：4 大屏统一 store schema + 联动协议，形成大屏联动"标准模式"
