## 1. Bug 清单

### Bug 1：038 人员信息 · 优抚对象构成下钻返回数据全 0 ✅（2026-10-26 修复）

- **大屏/模块**：038 人员信息大屏 · 模块5 优抚对象构成（条形图，entitled-object-bar-card → `/visual/big-screen/personnel/preferential`）
- **现象**：省级正常，地图下钻到市/区县后 6 类优抚对象数据全部为 0
- **根因**：
    1. 前端把地图派发的 ECharts 6 位 adcode（如 `210100`）直接作为 `cantCode` 传后端；
    2. `preferential.sql` 只做 `cant_code = 入参` 精确匹配（表 `abi_zb_tyjrjqyfdx` 内只有 4 位市级行 `2101`…），`210100` 匹配不到任何行 → SUM 全 0；
    3. 同表每日快照多行（`insert_time` 不同），preferential.sql 未取最新快照，与 total_detail.sql 不一致，存在多天重复计数隐患。
- **修复**：
    - Service：`get_preferential_data` → `_fetch_category` 复用 `_tyjrjqyfdx_cant_patterns()` 归一化（`21`/`210000` → `['21%']`；`210100`/`210102` → `['2101']`；抚顺含沈抚合并 `2104`+`2115`）
    - SQL：WHERE 改为 `cant_code LIKE ANY(%(patterns)s)`，并加 `insert_time = (SELECT MAX(insert_time) ...)` 最新快照条件（对齐 total_detail.sql）
- **涉及文件**：
    - `backend/app/repositories/sql/visual/big_screen/personnel/preferential.sql`
    - `backend/app/services/visual/big_screen/personnel.py`（get_preferential_data / _fetch_category）
- **已知口径限制**：表内只有市级 4 位行，区县下钻（`210102`）聚合到所在市（与 total/detail 同口径）
- **🛑 等待用户**：否
- **踩坑记录**：SQL 文件注释中裸写 `%`（如 `['21%']`）会导致 psycopg2 报 `dict is not a sequence`，注释中的 `%` 须写成 `%%`（同 employment.sql 的 `LIKE ... '%%'` 惯例）
- **验证（2026-10-26 真库）**：全省 `['21%']` → (20855, 1634, 10304, 156690, 4198, 4253)；沈阳 `['2101']` → (4595, 182, 935, 21070, 492, 1041)；抚顺合并 `['2104','2115']` → (759, 93, 236, 7024, 142, 303)，下钻不再全 0
