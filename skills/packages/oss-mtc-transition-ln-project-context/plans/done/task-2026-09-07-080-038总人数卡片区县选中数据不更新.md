## 1. 调查结论（已完成，2026-09-07）

### 1.1 现象

人员信息大屏（038 模块2）`RetireeTotalCard`：地图选中区县后卡片数据不变化（仍是所在市数据）。

### 1.2 前端链路排查（无问题）

- 地图 `data-overview/index.tsx` 的 `selectDistrict` 正确 dispatch `currentRegion = { adcode: 210102, level: 'district', parentCity, ... }`。
- `RetireeTotalCard` 订阅 `currentRegion`，`cantCode = String(region.adcode)` → `210102`，`fetchTotal` 依赖 `cantCode` 正确重拉 `/total?cantCode=210102`。前端无闭包陈旧 / 订阅失效问题。
- 组件内遗留调试 `console.log`（index.tsx:66）可顺手删除。

### 1.3 根因（后端数据源降级）

`backend/app/services/visual/big_screen/personnel.py` `_tyjrjqyfdx_cant_patterns(cant_code)`（L322-338）：

```python
# 210100 / 210102（市/区县）→ ['2101']（所在市）
if len(code) == 6:
    if code[2:] == "0000": return [f"{code[:2]}%"]
    code = code[:4]          # ← 区县 210102 被截短为 2101（所在市）
```

即 `/total` 的数据源 `dw_basic_lc.abi_zb_tyjrjqyfdx` **只有 4 位市级行，无区县粒度**，区县入参被有意降级为所在市 → 与下钻到该市时的返回完全相同 → 表现为"数据没更新"。下钻子集 `/total/detail` 同源同样只有市级粒度。

### 1.4 数据验证（本地库实测，临时脚本已删）

- `abi_zb_tyjrjqyfdx` 最新快照 cant_code 长度分布：仅 `(4, 15)` —— 15 个市级行，无区县行。
- `stats_jdlk_persion_infor_cant` province_code 长度分布：`(2,1) / (4,15) / (6,119)` —— **有 119 个区县行**，且含全部 5 个字段（VETERAN/OFFICER/SERGEANT/CONSCRIPTS/CAT_PRE_OBJECT），抽样和平区 210102：`(38553, 11937, 4358, 22102, 1561)`。
- 两表口径差异约 1%（沈阳：infor 合计 315785 vs abi 317424），与 total.sql 头注释一致。

### 1.5 结论

前端无 bug；根因是 `/total` 数据源 `abi_zb_tyjrjqyfdx` 无区县粒度且后端把区县降级到市。修复应走后端：区县级改查 `stats_jdlk_persion_infor_cant`（有区县行 + 全部 5 字段）。
