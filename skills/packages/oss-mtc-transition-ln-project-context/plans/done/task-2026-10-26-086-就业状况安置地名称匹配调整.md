## 1. 背景与问题

- **现场数据形态**：`aa_jycy."安置地"` 在现场库中是 **中文名称**，形如
  `辽宁鞍山 / 辽宁本溪 / 辽宁昌图 / 辽宁大连 / 辽宁大石桥 / 辽宁丹东 / 辽宁灯塔 / 辽宁调兵山 / 辽宁东港 / 辽宁法库 / 辽宁凤城 / 辽宁抚顺 / 辽宁阜新 / 辽宁盖州 / 辽宁海城 / 辽宁黑山 / 辽宁葫芦岛 / 辽宁建昌 / 辽宁锦州 / 辽宁康平 / 辽宁宽甸 / 辽宁辽阳`（含地级市 + 县级市/县）
- **本地开发库形态**：`"安置地"` 为 9 位数字码（`2101xxxxxx`，全沈阳）+ 约 10 行中文脏数据
- **现状**：employment.sql 按 `"安置地" LIKE '<adcode前缀>%'` 匹配 → **现场环境 0 命中，下钻全 0**
- task-085 已修复数字码归一化（本地有效），但未覆盖现场名称形态

## 2. 取值口径的关键难点

1. **名称里没有区划代码**，且 `辽宁` 前缀 + 地名（如 `辽宁昌图` = 铁岭昌图县；`辽宁大石桥` = 营口大石桥市）
2. **市级下钻不能只匹配市名**：该市下属的县级市/县名不含市名（如营口市下钻须同时命中 `辽宁营口` + `辽宁大石桥` + `辽宁盖州`），需「adcode → 该辖区全部地名集合」
3. 区县下钻同理：需 adcode → 区县名（如 `210281` → `庄河`）
4. 本地库（数字码）与现场库（名称）需兼容，避免本地回归

3. `get_employment_data()` 过滤改为：`"安置地" LIKE '<码前缀>%' OR "安置地" IN ('辽宁<名1>', ...)`，本地数字码 / 现场名称双形态兼容；省级仍不过滤
