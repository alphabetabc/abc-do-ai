## 0.2 现象

四个大屏的地图本体（`<EcMap>` 外层 div）尺寸设置不一致：

| 大屏             | 地图本体尺寸                    | 类型                             |
| ---------------- | ------------------------------- | -------------------------------- |
| **038 人员**     | `width: 835, height: '100%'`    | 半自适应（宽度固定、高度跟容器） |
| **039 辽宁信访** | `width: 717.32, height: 517.38` | 固定像素                         |
| **040 进京信访** | `width: 717.32, height: 517.38` | 固定像素                         |
| **041 信访比对** | `width: 100%, height: 100%`     | 完全自适应                       |

**核心症结**：

- 039 / 040 用了固定像素 `717.32 × 517.38`（小数点位明显是 hardcoded magic number）
- 038 / 041 走百分比自适应，但实现不一致（038 宽度 835 固定、041 完全 100%）
- 同一份 `<EcMap>` 组件接到不同外层尺寸时，渲染出的「可视地图」宽高比不一致

---

## 0.3 影响

- **跨大屏切换视觉跳跃**：用户从 038 切到 039，地图可视尺寸突变
- **响应式缺失**：屏幕尺寸变化时 039/040 固定像素不跟随
- **设计不规范**：magic number `717.32`（小数位）暗示是某个原始尺寸的产物（如 1920×1080 设计的等比缩放），但缺乏说明文档
- **同一份组件难以复用**：未来新增第 5 个大屏时，开发者不知道该用哪种尺寸方案

## 0.6 期望行为（待用户拍板）

核心问题：**「地图本体尺寸一致」具体指什么？**

| 候选解读                           | 说明                                                        |
| ---------------------------------- | ----------------------------------------------------------- |
| **解读 1**：可视区域宽高比一致     | 所有地图都按 16:9（或某个固定比例）渲染，容器给多大就填多大 |
| **解读 2**：可视区域宽高都一致     | 所有地图固定 `717×517`（或某个尺寸），不跟容器走            |
| **解读 3**：ECharts 内部坐标系一致 | 地图内部 `geo` 坐标系配置统一，不受外层像素影响             |

**对应实现方案**：

| 方案  | 对应解读      | 实现思路                                                                                | 优劣                                          |
| ----- | ------------- | --------------------------------------------------------------------------------------- | --------------------------------------------- |
| **A** | 解读 1        | 地图 `width: 100%, height: 100%`；父容器用 `aspect-ratio: 16/9`（或固定宽高比）控制尺寸 | ✅ 响应式；⚠️ 需 4 个父容器都按统一宽高比布局 |
| **B** | 解读 2        | 地图固定 `width: 717.32, height: 517.38`，抽常量到共享文件统一引用                      | ✅ 集中管理；❌ 不响应式                      |
| **C** | 解读 1+2 混合 | 抽公共尺寸常量 + 父容器宽高比统一 + 地图 100% 填充                                      | ✅ 既响应式又集中；⚠️ 改动量最大              |
| **D** | 解读 3        | 抽公共 ECharts 配置（如 `geo.layoutCenter`、`geo.layoutSize`），各页用同一配置          | ✅ 组件级复用；⚠️ 不解决外层 px 不一致        |

> **推荐方案 A 或 C**：聚焦"地图本体"用 100% 填充，**约束落在父容器**（038 横排、039/040 居中、041 卡片式各自决定宽高比，但宽高比必须一致）。

#### 遗留隐患（2026-09-03 用户报告：多次双击/下钻多地后返回异常）——分析结论：确认存在，038/039/040 三屏同源

**复现路径**：省视图双击地市 A（下钻）→ 双击/单击区县（选中）→ 不返回，直接双击另一地市 B？

不可能——市级视图里没有其他地市可点。真实复现是「下钻→返回→下钻→…多次」后栈内残留导致返回行为错乱。逐屏分析：

| 屏 | 问题机制 | 严重度 |
| --- | --- | --- |
| **039/040** | `selectDistrict` 每次选中区县都 `push`，但**重复点击同一/不同区县会连续压多层 district**（栈：省→市→区县a→区县b→区县c…），返回按钮 pop 一层只回「上一个区县」，需点 N 次才回到地市——用户感知「返回失灵」 | 高 |
| **039/040** | 双击区县时 `onDblClick` 前会先触发一次 `onClick`（`selectDistrict` 已执行+已压栈），随后 `onDblClick` 的 district 分支**再调一次 `selectDistrict` → 同一区县压栈两次**，栈膨胀 | 高 |
| **038** | `handleMapClick`/`handleDblClick` 同样双触发（单击先 selectDistrict 等价逻辑压栈，双击再压一次）；且 038 用 `setStack`（渲染态），连续 push 触发重渲染链 | 高 |
| **039/040（下钻叠加）** | 下钻多地序列：市 A 下钻→返回省→市 B 下钻…若某次「返回」走的是区县分支（prev.level==='city'）而非省分支，`currentAdcode` 未回 `210000`，地图视图与栈错位 | 中 |

**根因**：栈被用作「操作历史记录」而非「当前层级状态」。区县选中（无视图变化）不应入栈——041 正确用 `selectedNameRef`（覆盖式单值）管理区县选中，不入栈。

**修复方案（待拍板）**：区县选中**不入栈**，改 041 模型——`selectedNameRef` 覆盖记录 + `selectedDistrictRef`（存 adcode/parentCity）供返回第一段派发地市用；返回按钮判断「有区县选中→清选中+派发回地市（不 pop）」「无选中→pop 回省」。`handleBack` 不再依赖栈里有区县层。涉及 038/039/040 三个文件。

**修复记录（2026-09-03）**：✅ 已实施，tsc 通过。
- **039/040**：`selectDistrict` 不再压栈，改 `selectedDistrictRef`（覆盖式单值：adcode/name/parentCity）；双击地市下钻时清 `selectedDistrictRef` 残留；`handleBack` 重写为标准两段式（有选中→清高亮+派发回 parentCity 地市，不弹栈；无选中→pop 回省）。栈恒为「省→市」两层。
- **038**：新增 `setDistrictSelection`——栈顶已是 district 时**原地替换**（slice(0,-1)+push 新帧，栈不增长），否则 push 一层；`handleMapClick`/`handleDblClick` 区县分支均走替换式选中。`goBack` 原逻辑（弹栈即回上级+派发）天然正确，未改。
- 双击双触发问题（click 先执行 + dblclick 再执行）：由于选中是覆盖式，双触发只是同值覆盖两次，无副作用。
- 四屏区县选中机制统一为「覆盖式单值 + 返回第一段回地市口径」，栈仅承载 省→市 两级视图切换。

#### 回归修复（2026-09-03 用户报告两个 bug）——已修复，tsc 通过

1. **三屏到地市后单击/双击无选中效果（039/040）**
    - 根因：上一轮给 series 补 `selectedMode: false` 禁省级单击高亮时，同时禁掉了 `dispatchAction({type:'select'})` 的程序化高亮能力；而 `geoSelect` dispatch 因 geo 层 `selectedMode` 在 option.tsx L177 被注释而无效——两条高亮路全堵死。
    - 修复（039/040 各三处）：series 改 `selectedMode: 'single'`（保留 `silent: true` 阻断原生单击，省级单击仍无效果）；`selectDistrict` 改 `dispatchAction({type:'select', name})`；`handleBack` 改 `dispatchAction({type:'unselect', name})`。
2. **038 下钻地市后切换区县，各地区人数统计不更新**
    - 根因：区县改替换式入栈后栈顶 level 变 `'district'`，后续 `handleMapClick`/`handleDblClick` 判断 `cur.level === 'city'` 失败，区县切换被忽略、无派发。
    - 修复：038 两处区县分支改为允许 `cur.level === 'city' || cur.level === 'district'`，`parentCity` 在 district 栈顶时取 `cur.parentCity`。
3. **038 下钻到地市后单击/双击区县无选中高亮**
    - 根因：后端区县 key 可能是 9 位库码（如 210102000），`filterDistrictsToMap` 仅截前 6 位做过滤校验但保留原始 9 位 key；而点击派发的 `selectedAdcode` 来自 map-config 的 6 位码——seriesBuilder 里 `String(d.key) === String(selectedAdcode)` 恒不匹配 → 高亮分支永不命中。
    - 修复：038 seriesBuilder 比较改为 `String(d.key).slice(0, 6) === String(selectedAdcode)`（与 filterDistrictsToMap 的截位口径一致）。tsc 通过。
