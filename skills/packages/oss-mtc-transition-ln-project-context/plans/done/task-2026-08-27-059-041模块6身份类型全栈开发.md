## 2. 数据口径速览（详见 041 spec §3.3 模块6 + dme §2.6）

- 表：`dw_basic_lc.letter_screen_3`
- 字段（11 身份 × 1 行 = 11 列）：`SB_NCYWB` / `SB_CZYWB` / `SB_ZYSG` / `SB_FYSG` / `GB_JHFP` / `GB_ZZZY` / `GB_QYJZGB` / `GB_ZYJZGB` / `GB_JXGB` / `GB_FY` / `RY_QT`
- 查询次数：**2 次**（本地 `REG_AUTHORITY=2` 1 次聚合 + 进京 `REG_AUTHORITY=1` 1 次聚合；`ACCEPT_SOURCE ∈ {1,2,3}` 在 SQL 内 SUM）
- Service 层处理：直接 2 次调用 `query_local_and_beijing(organ_id, sql_template, params)` → 11 身份字段映射 categories；沈抚合并（`211500000` 行数值并入 `210400000` 抚顺行 × 2 组 = **共 2 次合并**）
- `ACCEPT_SOURCE=7`（特殊人员信访）过滤（spec O-N3）：SQL 内 `WHERE ACCEPT_SOURCE IN (1,2,3)`，**不包含 7**

**雷达图 11 指标轴（X 轴 / 雷达轴）**：

1. 农村籍义务兵
2. 城镇籍义务兵
3. 转业志愿兵/士官
4. 复员士官
5. 计划分配军转干部
6. 自主择业军转干部
7. 企业军转干部
8. 自谋自择就业军转干部
9. 军休干部
10. 复员干部
11. 其他

**2 series 拆分（双维度聚合，2026-08-28 简化版）**：

| 系列名   | 来源（维度） | ACCEPT_SOURCE（聚合渠道）              |
| -------- | ------------ | -------------------------------------- |
| series 1 | 本地         | {1,2,3} 求和（网上信访 + 来访 + 来信） |
| series 2 | 进京         | {1,2,3} 求和（网上信访 + 来访 + 来信） |

**响应形状（spec §3.3 / dme §2.6 大改版，2026-08-28 简化版）**：

```typescript
{
  // 11 身份作为雷达指标轴（前后端共享）
  categories: [
    '农村籍义务兵', '城镇籍义务兵', '转业志愿兵/士官', '复员士官',
    '计划分配军转干部', '自主择业军转干部', '企业军转干部', '自谋自择就业军转干部',
    '军休干部', '复员干部', '其他'
  ],
  // 2 series 拆分（2 维度聚合，ACCEPT_SOURCE {1,2,3} 求和）
  series: [
    { type: 'local',  name: '本地', data: [n1..n11] },
    { type: 'beijing', name: '进京', data: [n1..n11] }
  ]
}
```

> **大改说明（2026-08-27）**：原 spec 响应 `{ local: { categories, series }, beijing: { categories, series } }` 改为扁平结构 `{ categories, series }`，因为雷达图需要 **series 共用同一组 11 指标轴**（前端不能分两个雷达分别渲染，PM 拍板单雷达图多边形叠加）。
>
> **2026-08-28 二次简化**：进一步从 6 series（type × channel 正交两轴）简化为 2 series（仅 type，ACCEPT_SOURCE 在 SQL 内 SUM）。理由：渠道细分在雷达图上视觉信息冗余，单维度对比（本地 vs 进京）更清晰，且降低前后端复杂度。

- `query_local_and_beijing(organ_id, sql_template, params)` 双查询抽象
