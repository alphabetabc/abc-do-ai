## 3. 决策结果

### 3.1 端点路径形状 → **A 层级式**

`/api/visual/big-screen/{screen}/{module}`

screen = spec 目录名（personnel / petition-liaoning / petition-beijing / petition-compare）。
与 4 spec 天然对应；AGENTS §4 约定 `/api/visual/<sub-domain>` 天然契合。

### 3.2 参数传递 → **A query param**（修正：无 mode）

经查证 PM 需求，大屏不存在 `mode=latest` / `mode=year` 切换场景。大屏实际参数为 `cantCode` / `cantType`（地图下钻联动）等，统一走 query param，与所有既有 spec（035 / 019 / 023–033）一致。

### 3.3 鉴权粒度 → **A 4 个独立 key**

| screen       | 菜单 key                              |
| ------------ | ------------------------------------- |
| 人员信息大屏 | `visual-big-screen-personnel`         |
| 辽宁信访大屏 | `visual-big-screen-petition-liaoning` |
| 进京信访大屏 | `visual-big-screen-petition-beijing`  |
| 信访比对大屏 | `visual-big-screen-petition-compare`  |

与 035 的做法一致（035 有 7 个菜单 = 7 个 key）；与 4 spec + D-R4「4 平级菜单」一致。

### 3.4 响应结构 → **A 统一壳**

`{ code, message, data }`（`ApiResponse` 信封），与 035 及所有既有 spec 一致。

## 4. 决策组合（汇总）

| 项       | 决策                                                |
| -------- | --------------------------------------------------- |
| 端点路径 | `/api/visual/big-screen/{screen}/{module}`（A）     |
| 参数传递 | query param（cantCode / cantType 等，无 mode）（A） |
| 鉴权粒度 | 4 个独立菜单 key（A，与 4 spec 对应）               |
| 响应结构 | 统一壳 `{ code, message, data }`（A，与 035 一致）  |

**示例端点**：

```
GET /api/visual/big-screen/personnel/age-group?cantCode=21&cantType=4
  → require_menu_key("visual-big-screen-personnel")
  → { code: 0, message: "ok", data: { categories: [...], series: [...] } }
```
