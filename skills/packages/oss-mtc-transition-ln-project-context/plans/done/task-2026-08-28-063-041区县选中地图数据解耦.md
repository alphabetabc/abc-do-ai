### 1.1 两层刷新语义（定稿）

| 层级           | 操作                  | 周边模块          | 地图                                     |
| -------------- | --------------------- | ----------------- | ---------------------------------------- |
| 第一层（省级） | 双击地市下钻          | 刷新（organId→地市码） | 刷新（cantType '4'→'6' 切视图 + 数据重拉） |
| 第二层（市级） | 单击选中区县          | 刷新（organId→区县码） | **不刷新**（保持市级视图与数据）         |

## 2. 根因与方案

### 2.1 根因

`/map` useRequest 的 `refreshDeps` 原为 `[effectiveOrganId, effectiveCantType]`，直接订阅全局 organId——区县选中使 organId 变为 6 位区县码 → 地图必然重发请求。

### 2.2 mapQueryOrganId 解耦（已实施）

```tsx
// frontend/src/pages/visual/big-screen/petition-comparison/map/index.tsx
const mapQueryOrganId =
    effectiveCantType === '6' && Number(effectiveOrganId.slice(4)) !== 0
        ? currentAdcode
        : effectiveOrganId;

useRequest(
    () => getBigScreenPetitionComparisonMap({ organId: mapQueryOrganId, cantType: effectiveCantType }),
    { refreshDeps: [mapQueryOrganId, effectiveCantType], onError: () => message.error('地图数据加载失败') },
);
```

- 判定与 `presets.ts` `buildMapData` 的区县判定同款（`Number(code6.slice(4)) !== 0`）：cantType 为市级且 organId 末 2 位非 `00`（区县码）→ 请求参数归一化回市级 `currentAdcode`；省/市级码原样透传
- `refreshDeps` 改 `[mapQueryOrganId, effectiveCantType]`，与全局 organId 解耦

### 2.3 四场景推演（无中间态多余请求）

| 场景 | organId | mapQueryOrganId | /map 是否重发 |
| --- | --- | --- | --- |
| 省级双击下钻 | 地市 9 位码（原子写入同帧可达） | = organId（不满足区县判定，不归一化） | ✅ 一次，无中间态 |
| 市级单击选中区县 | 区县码（末2位非00） | 锁定 `currentAdcode`（市级） | ❌ 参数不变不重发 |
| 取消选中 / 点空白 | 回 `currentAdcode` | = `currentAdcode` | ❌ 参数不变不重发 |
| 返回省级 | `'210000'` | = organId（cantType 变 '4'） | ✅ 一次 |

### 2.4 TDZ 错误与修复

初版将 `mapQueryOrganId` 计算插在 `/map` 拉取块，但引用了其后才声明的 `const currentAdcode` → 「Cannot access 'currentAdcode' before initialization」。修复：`currentAdcode` / `prevCantTypeRef` / `mapEcRef` / `selectedNameRef` 四组声明上移至 `/map` 拉取块之前（视图 state/refs → /map 拉取 → 视图 effect）。
