## 4. 决策记录

### 4.1 方案 A vs 方案 B 选型（2026-09-01 用户拍板：方案 A）

**用户原话**："不要管 039 和 041 ，我们先讨论我们的，我把它放到后端就是为了容易维护"

**评估对比**：

| 维度           | A. Service Python helper（采纳）                                                                                                         | B. SQL 派生（CTE + generate_series）                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 单测基建       | ✅ Python pytest 完整（已有 `test_big_screen_petition_comparison_trend.py`），helper 一行 `assert _build_xaxis(date(2026,9,1)) == [...]` | ⚠️ 项目内**无 SQL 单测基建**——SQL 改动只能依赖 mock 模式 + 真库回归   |
| mock 同步      | ✅ mock/real 都走同一个 helper，派生逻辑唯一                                                                                             | ❌ mock 模式**不走 SQL**，派生逻辑要在 Python 再写一份 → 两套派生来源 |
| 分层清晰度     | ✅ SQL = 数据查询；Service = 派生 + 装配                                                                                                 | ❌ 把"展示标签格式"耦合进数据查询层，违反分层                         |
| 改锚点成本     | ✅ 改一处（helper）                                                                                                                      | ⚠️ 改 SQL + 改 mock Python 两处                                       |
| 复用性         | ✅ `_build_xaxis(now)` 纯函数可跨模块复用                                                                                                | ❌ SQL 派生逻辑没法跨模块复用                                         |
| SQL 可读性     | ✅ 维持 17 行                                                                                                                            | ❌ CTE + generate_series + array_agg + date_trunc → 30+ 行            |
| 与既有先例一致 | ✅ task-066 rank 服务端化 = Service 层做（`_RANK_CITIES` + `_fill_rank_city_full_set` + `_build_rank_response`）                         | ❌ 无同类先例                                                         |

**结论**：方案 A 更易维护——SQL 单一职责不被破坏、Python 单测基建成熟、mock/real 一致、可复用、与 task-066 模式对齐。
