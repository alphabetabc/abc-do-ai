# 发包指南（前端 / 后端 · Docker / 裸机）

> 面向发包人员的一页式梳理：说清楚前端怎么发、后端怎么发、用 Docker 怎么发、不用 Docker 怎么发。
> 本文为 skill 私人参考，正式交付文档以 `README.md`、`prod/README.md`、`prod/KirinV10-application-deployment/` 为准。

---

## 0. 总览：两条交付路线

| 路线 | 适用现场 | 交付物 | 上线方式 |
| --- | --- | --- | --- |
| **A. Docker 离线包** | 允许 Docker 的生产节点（银河麒麟 Kylin-10-SP3-X86 等） | `pdva-full-stack-<时间戳>.zip`（含镜像 tar + compose + env 模板） | `docker load` → `docker compose up -d` |
| **B. 麒麟 V10 裸机包** | **禁止 Docker** 的现场 | `pdva-kylin-v10.zip`（前端 dist + 后端源码 + 离线 wheels + TongHttpServer 配置 + 启停脚本） | 解压 → 配 env → `start.sh` |

公共事实：

- **数据库永远是外部 Kingbase**，compose / 交付包均不含数据库容器；发包前需在 `.env` / `env.host.example` 中配置现场 Kingbase 连接（端口 54321、oracle 兼容模式、search_path）。
- **DDL 迁移自动执行**：Docker 路线由后端容器 entrypoint（`RUN_MIGRATE_ON_START` 默认 true）跑 `alembic upgrade head`；裸机路线由 `start.sh` 自动跑。
- **版本管理现状**：镜像 tag 恒为 `latest`，版本区分只靠 zip 文件名时间戳；无 CHANGELOG。
- **种子数据**：现场首次部署或升级后需幂等执行 `scripts/run_seed_prod_baseline.py`（菜单、admin、字典；不含演示数据）。
- **党建模块（044/045/046）未验收**，保底种子默认隐藏其菜单；激活需 `run_seed_party_menus.py`（详见 `prod/KirinV10-application-deployment/打包与物料准备指引.md` §6）。

## 1. 前端怎么发

### 1.1 构建（两路线共用的源头）

```bash
cd frontend
pnpm install
pnpm run build        # = tsc -b && vite build，产物 frontend/dist/
```

要点：

- `package.json` 为 `private: true`，**不走 npm publish**，「发前端」= 产出静态 `dist/`。
- base 路径由 `VITE_APP_BASE` 环境变量控制（默认 `/pdva/`），与部署基准路径对应。
- 构建产物确认：`dist/index.html` + `dist/assets/` 存在。

### 1.2 Docker 场景发前端

前端 `frontend/Dockerfile` 多阶段构建：`node:22-alpine` 里 pnpm build → 产物 COPY 进 `nginx:1.27-alpine`，由 `frontend/nginx.conf` 提供静态托管 + `/pdva/api`、`/api` 反代到 `backend:8000` + SPA fallback。

```bash
# 手动方式（仓库根，配合 .env.docker）
docker compose --env-file .env.docker build frontend
docker compose --env-file .env.docker up -d frontend
```

产物镜像名：`pdva-frontend:latest`。随全栈包一起交付（见 §3.1）。

### 1.3 非 Docker 场景发前端

前端 `dist/` 原样拷入裸机交付目录，由信创中间件 **东方通 TongHttpServer V6.0**（备选 Nginx）托管：

```powershell
New-Item -ItemType Directory -Force -Path "prod\KirinV10-application-deployment\frontend"
Copy-Item -Recurse -Force "frontend\dist" "prod\KirinV10-application-deployment\frontend\"
```

站点反代规则见 `prod/KirinV10-application-deployment/tonghttpserver.conf.example`（`/nginx.conf.example` 为备选）。

## 2. 后端怎么发

### 2.1 构建 / 依赖

- 依赖定义：`backend/pyproject.toml` + `uv.lock`（hatchling，version 0.1.0，**不走 pip / PyPI 发布**）；`backend/requirements.txt` 为 `uv export` 生成的裸机离线安装用清单。
- 运行方式：`uv run uvicorn app.main:app --host 0.0.0.0 --port 8000`（单进程 uvicorn）。
- 结构迁移：alembic，连接串由 `app` Settings 注入，无需改 `alembic.ini`。

### 2.2 Docker 场景发后端

`backend/Dockerfile`：`python:3.11-slim` + uv，COPY app/alembic/db/scripts，`uv sync --frozen --no-dev`，非 root 用户，健康检查 `/health`。

```bash
# 手动方式（仓库根）
docker compose --env-file .env.docker build backend
docker compose --env-file .env.docker up -d backend
```

产物镜像名：`pdva-backend:latest`。容器启动自动执行 `alembic upgrade head`（entrypoint `docker-entrypoint.sh`，`RUN_MIGRATE_ON_START` 控制）。

### 2.3 非 Docker 场景发后端

后端**以源码 + 离线依赖**形式交付（Kylin-10-SP3-X86 兼容 Linux x86_64 / glibc）：

1. 拷贝后端代码与依赖声明到交付目录：

```powershell
New-Item -ItemType Directory -Force -Path "prod\KirinV10-application-deployment\backend"
"app", "db", "alembic", "scripts", "alembic.ini", "pyproject.toml", "uv.lock", "requirements.txt" |
  ForEach-Object { Copy-Item -Recurse -Force "backend\$_" "prod\KirinV10-application-deployment\backend\" }
```

2. 首次发包或依赖变更时，预下载全量 Linux x86_64 wheels（推荐 Docker 临时容器，本地无需装 Python 3.11）：

```powershell
docker run --rm -v "${PWD}:/workspace" -w /workspace python:3.11-slim bash -c "
  mkdir -p prod/offline-environment/wheels && \
  pip install --no-cache-dir uv && \
  cd backend && \
  uv export --no-dev --no-emit-project --no-hashes -o requirements.txt && \
  pip download -d ../prod/offline-environment/wheels -r requirements.txt
"
```

3. 现场由 `offline-environment/` 内的离线 Python 3.11 + uv 安装运行时，`scripts/start.sh` 一键启动（自动迁移 + 字体 + 端口检查），`pdva-backend.service` 提供 systemd 守护；启停用 `stop.sh` / `restart.sh` / `status.sh`。

## 3. 用 Docker 怎么发（路线 A 全流程）

### 3.1 首选：Jenkins 一键流水线

仓库根 `Jenkinsfile`（声明式 pipeline），关键参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `BRANCH` | develop | 发包分支 / Tag / Commit |
| `PORT_CONFIGS` | frontend:18086,backend:18001 | 宿主机端口映射 |
| `BASE_PATH` | /pdva | 应用基准路径（对应前端 VITE_APP_BASE） |
| `BUILD_FRONTEND` / `BUILD_BACKEND` | true | 可只发一端 |
| `DEPLOY_LOCAL` | true | 是否同时部署到 Jenkins 节点 |
| `RUN_PROD_BASELINE_SEEDS` | false | 部署后是否跑现场保底种子 |
| `ZIP_PACKAGE` | **false** | **勾选后导出镜像并压缩成交付 zip** |

流程：Initialize → 从 `.env.docker.example` 生成 `.env.docker`/`.env` → compose 串行构建镜像 → 本地部署 → 可选种子 → 勾选 `ZIP_PACKAGE` 时 `docker save` 出 `pdva-full-stack-<时间戳>.zip`（Jenkins artifacts，保留最新 10 个）。

### 3.2 手动打包（不经 Jenkins）

```bash
# 仓库根：构建镜像
docker compose --env-file .env.docker build

# 导出镜像到 prod/
docker save pdva-backend:latest pdva-frontend:latest -o prod/images/pdva-full-stack.tar

# 连同 prod/ 目录（docker-compose.yml + env.example + db-tools 等）压缩交付
```

### 3.3 现场上线 3 步（见 prod/README.md §3）

```bash
cd prod
cp env.example .env && vi .env     # 改 SECRET_KEY、DB_*、CORS_ORIGINS
docker load -i images/pdva-full-stack.tar
docker compose --env-file .env up -d
# 首次还需跑保底种子：
docker compose --env-file .env run --rm -e DB_MODE=real backend uv run python scripts/run_seed_prod_baseline.py
```

### 3.4 现场升级

`docker load` 新镜像 → `compose down` / `up -d`（自动 DDL 增量迁移）→ 幂等重跑 `run_seed_prod_baseline.py`（见 `prod/README.md` §6）。

## 4. 不用 Docker 怎么发（路线 B 全流程，麒麟 V10 裸机）

权威文档：`prod/KirinV10-application-deployment/打包与物料准备指引.md`（发包侧）+ 同目录 `README.md`（现场侧）。

发包侧组装清单（有网开发机上完成）：

1. **前端 dist**：`pnpm run build` → 拷入 `KirinV10-application-deployment/frontend/dist/`（§1.3）
2. **后端源码 + 依赖声明**：拷入 `KirinV10-application-deployment/backend/`（§2.3）
3. **离线 wheels**：仅首次发包或依赖变更时下载到 `offline-environment/wheels/`（§2.3）
4. **中文字体**：报表导出需要时放 `offline-environment/fonts/`（如 `simsun.ttc`），可从 Windows Fonts 复制
5. **打包交付**：将 `prod/` 下 `offline-environment/`、`KirinV10-application-deployment/`、`db-tools/` 三目录压缩为 `pdva-kylin-v10.zip`，发送现场（**不含** Docker 镜像与编排文件）

现场侧：解压 → `offline-environment/check-env.sh` 体检 → 配 `env.host.example` → `scripts/start.sh` 启动。现场升级见同目录《现场前后端升级指引.txt》。

两套路线数据格式一致，可互相回退。

- [ ] 确认目标现场走 Docker 还是裸机路线
