1. 设计语言 为什么这样定
维度取值理由
基调浅色后台 · 白卡片 + 浅灰底贴合 Coze/低代码平台心智，「业务用户可用」而非「工程师工具」
主色#2b6de8（科技蓝）可信、操作引导明确；避开大屏深色，形成「工作台浅 / 画布深」的分区对比
画布区保留深色（#0b1220）大屏渲染区天然深色，浅色工作台包裹深色画布 = 舞台聚光效果，演示爆点被突出
圆角/描边小圆角（4-10px）+ 细描边克制、专业，不讨好式的圆滚滚

8. 工作区专属规则 浅 × 深同屏
区域规则
左侧聊天面板中性底 surface2 底；Hermes iframe 嵌入区带 1px 描边圆角框；收起后变 44px 窄条（仅保留 « » 按钮）
用户气泡primary 蓝底白字（右上）；助手气泡白底描边（左上）—— 与微信类心智一致
MCP 轨迹12px mono 弱色，左侧 2px 蓝色竖线；不参与视觉竞争
引导点选项描边蓝 pill，选中态 primary-bg + 加深文字
右侧呈现区深色 #0b1220 + 内衬 8px 深色边；画布内组件物料自带样式（物料站产物，不归本规范管）
呈现区视图切换默认画布视图；顶栏「大屏 / 文档」切换至文档视图（文件管理器布局，只读）：左侧为场景实际项目的完整目录树（src/components/materials 物料与 registry、src/screens、public/schemas、public/vendors、public/assets、package.json 等，项目是什么就展示什么），右侧选中文件内容预览（代码/JSON 语法高亮；图片内联预览；MCP 写入的文件或变更节点黄色标注）。无任何编辑入口；切换为瞬时 tab，不丢画布状态
9. Hermes iframe 主题适配 实测结论 2026-11-17
事实说明
Hermes 跟随系统颜色实测 html.dark + prefers-color-scheme 响应；另有用户级主题定制（hermes_theme_customization_v1：字号/文字色/强调色）
平台应用固定浅色，不跟随系统——零代码产品心智统一
一致性要求演示/交付环境系统设为浅色模式（或浏览器 DevTools 强制 prefers-color-scheme: light），iframe 即呈浅色，与外壳同域
深色兜底系统为深色时 iframe 允许呈深色，不视为缺陷；聊天面板容器用中性底 #eef0f4 + 圆角描边，两种系统色下均可衬
结论：不需要为 iframe 做三段式深色域。唯一硬要求是演示机系统颜色 = 浅色，写进演示 SOP 的环境检查项。
