### 1.2 ⚠️ 新发现 2：`syncLayoutBlockSize2Children` 内部全 mutation（阶段 1 §1.14 + 阶段 3 §1.3 遗漏）

**文件**：[`src/designer/common/field/layout-block/helper/element.tsx`](../../../../src/designer/common/field/layout-block/helper/element.tsx) L58-L120

```ts
const syncLayoutBlockSize2Children = (layoutBlockConfig: any, children: any[]) => {
    // ...
    return children.map((child) => {
        // ⚠️ _.set 是 lodash 的 in-place mutation（修改 child.data.config.width 等）
        _.set(child, 'data.config.width', width);
        _.set(child, 'data.config.height', height);
        _.set(child, 'data.config.left', 0);
        _.set(child, 'data.config.top', 0);

```

**调用方（3 处）**：

| 调用方 | 触发场景 | 状态 |
| --- | --- | --- |
| [`drag2layoutBlock.ts:49`](../../../../src/designer/common/draggable/drag2layoutBlock.ts) | `onDragStop → dropToGroup` 把组件拖入 layout-block | 阶段 1+3 漏 |
| [`useOnDrop.ts:30`](../../../../src/designer/aside-panel/layers-tree/tree/useOnDrop.ts) | 图层树拖拽到 layout-block 节点 | 阶段 1 §1.14 已知，但未分析被调函数 |
| [`element.tsx:123`](../../../../src/designer/common/field/layout-block/helper/element.tsx)（`setChildren2LayoutBlock` 函数定义）→ `element.tsx:136`（内部调用 `syncLayoutBlockSize2Children`）→ [`DropContainer.tsx:63`](../../../../src/designer/common/dnd/DropContainer.tsx)（行号修正：原 L64 实为 L63） | 从素材面板拖入 layout-block 区域 | 阶段 1+3 漏 |

**关键问题**：
- `syncLayoutBlockSize2Children` 内部用 `_.set` + `child.children = ...`，**所有 child 对象引用都被原地修改**
- 即使调用方传 `[...children, dropField]`（新数组），数组里的 child 仍然是原 tree 的浅引用
- 结果：**原 tree 的子节点被原地修改**（尺寸/位置数据被覆盖）
- 单源后 reducer 接收这种 tree，`buildIndex(draft.components)` 读取的也是被 mutate 过的 data

**含义**：
- 阶段 1 §1.14 只列了 `useOnDrop L28/L61` 两处直接 mutation，**未识别 `syncLayoutBlockSize2Children` 这个"深层 mutation 源"**
- 阶段 3 §1.3 的 "useOnDrop mutation 修复方案" 没有覆盖到 `syncLayoutBlockSize2Children`
- 实际上，**仅修复 `useOnDrop L28/L61` + `drag2layoutBlock L49` 仍不够**——必须让 `syncLayoutBlockSize2Children` 本身返回不可变的新对象

**单源后影响**：
- 同 `useOnDrop` 的 mutation 问题（Immer produce 信任 mutate 后 tree，但 shallowEqual / useFieldConf 订阅可能拿到错值）
- **3 个调用路径**都需要从根上修复才能消除隐患

### 1.3 阶段 3 §1.6 假设复核：`recursion-components` 删除节点过滤

### 1.4 `useSaveCompDetailData4Designer.ts` 阶段 3 §3.5 判定复核

阶段 3 §3.5 标 `useSaveCompDetailData4Designer.ts:30` 为"双源"风险：

**实际验证**：
- L18: 读 `pageConfig.components`（来自 props.pageInfo.config，是**外部传入的**，不是 Redux state）
- L30: `buildIndex(components)` 是**对外部传入的 components** 建索引，**不是对 Redux state.byId 建索引**
- L32: `generatorGroup(components, byId, parentMap, ...)` 是把**刚建的 byId/parentMap** 传给 generatorGroup 参数

**判定修正**：
- **这不是"双源"**——它不读 Redux state 的 byId/parentMap，**自建 byId/parentMap 用于 generatorGroup 的参数传递**
- generatorGroup 在阶段 2 决策 11 中**保留签名**（仍接收 byId/parentMap 参数）
- 因此 `useSaveCompDetailData4Designer.ts` 的调用模式**完全不需要改**——只要 `buildIndex` 函数签名不变（不会变），它就安全
- **阶段 4 步骤 -1 的产出**：只需确认此文件确实不读 Redux state，**确认无修改**

### 1.5 Immer 版本复核

阶段 3 §1.3 假设 (A1)："基于 Immer 9.x 文档"

**实际验证**：[`package.json:24`](../../../../package.json) → `"immer": "^9.0.6"`

**含义**：
- Immer 9.0.6 是 Immer 9.x 系列
- Immer 9.x 的 freeze 行为：produce 完成后会冻结结果（除非 setAutoFreeze(false)）
- mutate 后传入 produce：Immer 信任 mutate 后的对象，**不冻结**（仅冻结 produce 回调内通过 draft 修改的部分）
- **mutate 后的子节点引用若被 useFieldConf shallowEqual 比较**，可能误判"无变化"——这是真正的风险

```ts
const syncLayoutBlockSize2Children = (layoutBlockConfig: any, children: any[]) => {
    const width = _.get(layoutBlockConfig, 'data.config.width');
    const height = _.get(layoutBlockConfig, 'data.config.height');

    const resizeChildren = (childrenList: any, parentSize: any): any[] => {
        if (!_.isArray(childrenList) || childrenList.length === 0) return childrenList;
        if (childrenList.length === 1) {
            return childrenList.map((child: any) => {
                const oWidth = _.get(child, 'data.config.width');
                const oHeight = _.get(child, 'data.config.height');
                const newChild = {
                    ...child,
                    data: {
                        ...child.data,
                        config: {
                            ...child.data.config,
                            width: parentSize.width,
                            height: parentSize.height,
                            left: 0,
                            top: 0,
                        },
                    },
                };
                if (child.children) {
                    // NaN 防护：oWidth/oHeight 为 0 时 xScale/yScale = NaN/Infinity
                    // 对比 utils.ts:603-607 既有防护 if (isNaN(scaleX)) scaleX = 1;
                    const xScale = oWidth ? parentSize.width / oWidth : 1;
                    const yScale = oHeight ? parentSize.height / oHeight : 1;
                    newChild.children = resizeChildren(child.children, {
                        width: parentSize.width,
                        height: parentSize.height,
                        xScale,
                        yScale,
                    });
                }
                return newChild;
            });
        } else {
            return childrenList.map((child: any) => {
                const childWidth = _.get(child, 'data.config.width');
                const childHeight = _.get(child, 'data.config.height');
                const left = _.get(child, 'data.config.left');
                const top = _.get(child, 'data.config.top');
                const newChild = {
                    ...child,
                    data: {
                        ...child.data,
                        config: {
                            ...child.data.config,
                            width: parentSize.xScale * childWidth,
                            left: parentSize.xScale * left,
                            height: parentSize.yScale * childHeight,
                            top: parentSize.yScale * top,
                        },
                    },
                };
                if (child.children) {
                    newChild.children = resizeChildren(child.children, parentSize);
                }
                return newChild;
            });
        }
    };

    return children.map((child) => {
        const oWidth = _.get(child, 'data.config.width');
        const oHeight = _.get(child, 'data.config.height');
        const newChild = {
            ...child,
            data: {
                ...child.data,
                config: {
                    ...child.data.config,
                    width,
                    height,
                    left: 0,
                    top: 0,
                },
            },
        };
        if (child.children) {
            // NaN 防护
            const xScale = oWidth ? width / oWidth : 1;
            const yScale = oHeight ? height / oHeight : 1;
            newChild.children = resizeChildren(child.children, { width, height, xScale, yScale });
        }
        return newChild;
    });
};
```

```ts
case 'designerCanvas/updateFieldConfig': {
    const { uniqueId, patch } = action.payload;

    // ===== 边界检查（produce 外面）=====
    // 边界 1：ROOT 是虚拟根，不在 byId/parentMap 中
    if (uniqueId === ROOT_UNIQUE_ID) return state;
    // 边界 2：parentMap 不存在的 id（组件已删除），忽略
    if (!state.parentMap[uniqueId]) return state;
    // 边界 3：patch 为空，直接返回原 state（避免无意义 buildIndex）
    if (!patch || (typeof patch === 'object' && Object.keys(patch).length === 0)) {
        return state;
    }

    return produce(state, (draft) => {
        // ===== 1. parentMap 反向追踪找路径 O(depth) =====
        const path: string[] = [];
        let current: string = uniqueId;
        // 依据：440 组件场景实测最深 layout-block 嵌套 ≈ 10 层，100 是 10 倍冗余
        // 前置递增：depth 从 1 开始计数，达到 MAX_DEPTH 时立即退出（避免 +1 后才退出的歧义）
        let depth = 0;
        const MAX_DEPTH = 100;
        while (current !== ROOT_UNIQUE_ID) {
            path.unshift(current);
            const next = draft.parentMap[current];
            if (!next) return;  // parentMap 不一致：放弃本次更新（防御）
            if (++depth >= MAX_DEPTH) {
                console.error('[updateFieldConfig] 超过最大深度', MAX_DEPTH, 'uniqueId:', uniqueId);
                return;
            }
            current = next;
        }

        // ===== 2. 沿路径找到节点 O(depth) =====
        // 修正：draft.components 是数组（[designer-canvas.ts:23]），不是带 children 的根节点
        // buildIndex 内部 walk([...], ROOT_UNIQUE_ID) 也确认顶层是数组
        let currentChildren: any[] = draft.components;
        let node: any = null;
        for (const id of path) {
            // 防御：currentChildren 可能是 undefined（数据损坏场景）
            node = currentChildren?.find((c: any) => c.uniqueId === id) ?? null;
            if (!node) return;  // 树与 parentMap 不一致：放弃本次更新（防御）
            currentChildren = node.children || [];
        }

        // ===== 3. 修改节点 data（浅合并：深嵌套字段需调用方传完整对象）=====
        node.data = {
            ...node.data,
            ...patch,
            config: patch.config ? { ...node.data.config, ...patch.config } : node.data.config,
        };

        // ===== 4. buildIndex 重建 byId/parentMap O(n)，引用复用保持订阅粒度 =====
        // 缓解方案（：对"data 未变化的节点"复用旧 byId 条目引用——保持 useFieldConf shallowEqual 不触发
        // 必须在 produce 内调用（接受旧 state.parentMap 作为对比基准，否则无法判断"未变"）
        const { byId, parentMap } = buildIndex(draft.components, draft.byId);
        draft.byId = byId;
        draft.parentMap = parentMap;
    });
}
```

**⚠️ 须同步修改 `buildIndex` 函数签名**（[utils.ts:784](file:///e:/oss-fe-git/frame/oss-visual-designer/src/designer/renderer/utils.ts#L784-L784)）：

```ts
export function buildIndex(components: any[]): { byId: Record<string, FlatField>; parentMap: Record<string, string> } {
    const byId: Record<string, FlatField> = {};
    const parentMap: Record<string, string> = {};
    const walk = (nodes: any[], parentId: string) => {
        for (const node of nodes || []) {
            byId[node.uniqueId] = {
                uniqueId: node.uniqueId,
                type: node.type,
                parentId,
                data: node.data,
            };
            if (Array.isArray(node.children) && node.children.length > 0) {
                walk(node.children, node.uniqueId);
            }
        }
    };
    walk(components || [], ROOT_UNIQUE_ID);
    return { byId, parentMap };
}

// 新签名（增加可选参数 oldById 用于引用复用）
export function buildIndex(
    components: any[],
    oldById?: Record<string, FlatField>,
): { byId: Record<string, FlatField>; parentMap: Record<string, string> } {
    const byId: Record<string, FlatField> = {};
    const parentMap: Record<string, string> = {};
    const walk = (nodes: any[], parentId: string) => {
        for (const node of nodes || []) {
            // 引用复用（缓解方案）：data 未变化时复用旧条目，保持 shallowEqual 订阅粒度
            const oldEntry = oldById?.[node.uniqueId];
            byId[node.uniqueId] = (oldEntry && oldEntry.data === node.data)
                ? oldEntry
                : { uniqueId: node.uniqueId, type: node.type, parentId, data: node.data };
            if (Array.isArray(node.children) && node.children.length > 0) {
                walk(node.children, node.uniqueId);
            }
        }
    };
    walk(components || [], ROOT_UNIQUE_ID);
    return { byId, parentMap };
}
```

**说明**：`buildIndex` 的 parentMap 始终重建（结构信息必变），byId 才需要引用复用。

**需新增 import**：`ROOT_UNIQUE_ID` 从 `@Src/designer/renderer/utils`（若未导入）

**核心改动**：
1. **数据结构修正（**：`draft.components` 是数组，遍历用 `currentChildren` 而非 `node.children`
2. **契约缓解（高优先级）**：`buildIndex(components, oldById)` 内部对未变 data 节点复用旧 byId 引用——保持 useFieldConf shallowEqual 订阅粒度不被破坏
3. **Immer 语义修正（**：produce 内全部 `return state` 改为 `return;`（Immer 惯例：不返回值等价于"放弃本次修改"）
4. **MAX_DEPTH 阈值依据（+ ）**：注释 100 的来源（10 倍冗余），前置递增 `++depth >= MAX_DEPTH` 语义清晰
5. **防御性编程（**：parentMap 不一致 / 树与 parentMap 不一致 / 空 patch / currentChildren undefined 全部走 `return;` 静默放弃（保留原 state），并对 MAX_DEPTH 触发 console.error
6. **patch 为空检查**：避免无意义的 buildIndex（即使 patch 为空也会触发 O(n) 重建）
