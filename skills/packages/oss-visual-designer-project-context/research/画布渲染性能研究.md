# 画布渲染性能研究

> 研究日期：2026-07-23
> 触发原因：选中图层 / 修改属性时，所有 ItemField 全量重渲染（console.log 验证）
> **更新（2026-07-23 第二轮）**：P0/P1 优化后问题依然存在，深度排查发现根因是 `RecursionComponents` 缺少 `React.memo`，导致重渲染链路从源头未被截断。

---

## 零、根因（第二轮排查结论）

### 重渲染链路

```
component.selected 变化
    ↓
DesignerContent L112: useSelector(fullState => fullState.component)
    ← 订阅整个 component slice，无 shallowEqual，任何 component 字段变化都 re-render
CanvasGraph L112: useSelector(fullState => fullState.component.selected)
    ← selected 变化也触发 re-render
    ↓ 两者同时 re-render
CanvasGraph (forwardRef, 无 React.memo)
    → 渲染 {props.children}
    ↓
RecursionComponents (无 React.memo ← 关键缺失)
    → useMemo 返回缓存 JSX，但组件函数体仍执行
    → React 仍需 reconcile 所有 DesignerField 子节点
    ↓
DesignerField (memo + areEqual)
    → useSelector 内部使用 useSyncExternalStore
    → useSyncExternalStore 的 forceUpdate 会绕过 memo 的 areEqual 比较
    → selected 变化时所有 DesignerField 的 useSelector 被通知
    → 即使 areEqual 返回 true，useSyncExternalStore 仍触发重渲染
    ↓
ItemField (无 memo)
    → 全量重渲染
```

### 修复

`RecursionComponents` 添加 `React.memo`。当 props（`enableWidgetMovable` / `onValueChange`）不变时，`RecursionComponents` 自身不重渲染，整个子树的 reconcile 全部跳过，`DesignerField` 的 `useSelector` 也不会被触发。

```tsx
// 旧
export const RecursionComponents = (props) => { ... };

// 新
const RecursionComponentsImpl = (props) => { ... };
export const RecursionComponents = memo(RecursionComponentsImpl);
```

### 为什么 P0/P1 没解决

P0（ItemField 派生布尔值）和 P1（DesignerField 去掉 components 订阅）都是正确的优化，但它们处理的是**下游**（叶子节点）的重渲染，没有截断**上游**（RecursionComponents）的重渲染链路。`RecursionComponents` 每次 re-render，React 必须 reconcile 所有子节点，而 `DesignerField` 的 `useSelector`（useSyncExternalStore）会绕过 `memo` 的 `areEqual` 触发重渲染。

## 一、渲染链路全景

```
DesignerContent.tsx (L446)
  └─ <RecursionComponents onValueChange={...} enableWidgetMovable={...} />
       │  ① useSelector(s => s.designerCanvas.components, shallowEqual)  ← 整树订阅
       │  useMemo([components, onValueChange, enableWidgetMovable]) 递归遍历
       │
       └─ <DesignerField key={uniqueId} dataSource={item} ...>  ← props 传 dataSource
            │  ② useFieldConf(uniqueId)                           ← 字段级订阅 byId[id]
            │  ③ useSelector(fullState => {                       ← 订阅 selected
            │       hasSelected: selectedIds.includes(uniqueId)
            │     }, shallowEqual)
            │  ④ useSelector(s => s.designerCanvas.components)     ← 整树订阅（再次！）
            │  ⑤ useViewScale()                                   ← 订阅画布缩放
            │  memo(DesignerField, areEqual)                      ← React.memo（只拦 props）
            │

                 │  按 type 分发：
                 │  - GROUP → <GroupField>
                 │  - LAYOUT_BLOCK → <LayoutBlock>

                 │
                 └─ <ItemField>  ← 无 React.memo
                      │  ⑥ useSelector(state => ({

                      │  DataFetcherPlugin.useFetchData(...)

                      │
                      └─ <Field {...mergedProps} />  ← 实际物料组件
```

## 二、根因分析

### 问题 1：选中图层时全量重渲染

**根因链**：

1. 点击组件 → `dispatch({ type: 'component/selected', data: id })` → Redux `component.selected` 变化
2. **DesignerField ③**：每个 DesignerField 都 `useSelector` 订阅了 `component.selected`，selector 函数返回 `{ hasSelected, selectedFieldInGroup, modalVisible, designerType }`
   - `shallowEqual` 比较：只有 `hasSelected` 从 false→true（或 true→false）的组件会重渲染
   - **但 selector 函数本身会在所有 DesignerField 中执行**（440 个组件 = 440 次 selector 执行）
   - `hasSelected` 只有 2 个组件变化（上一个取消 + 本次选中），理论上只应 2 个重渲染
   - **这部分是正确的**，shallowEqual 拦住了未变化的重渲染

3. **ItemField ⑥**：每个 ItemField 也 `useSelector` 订阅了 `component.selected`
   ```ts
   const { selected, receivedPropsParams } = useSelector(
       (state: any) => ({
           selected: state.component.selected,           // ← 原始字符串
           receivedPropsParams: state.component.querys.receivedPropsParams,
       }),
       _.isEqual,  // ← 深比较
   );
   ```
   - **问题**：selector 返回的 `selected` 是**原始字符串**（如 `"comp_001"`），不是派生布尔值
   - 选中变化时 `selected` 字符串变了 → `_.isEqual` 判定不等 → **所有 ItemField 全部重渲染**
   - 即使 `selected` 只在 L164 `{selected === fullProps.uniqueId && <DataDebug />}` 一处使用

**结论**：选中图层时全量重渲染的**直接原因**是 ItemField 的 `useSelector` 返回了原始 `selected` 字符串，而非派生的布尔值。`_.isEqual` 深比较无法拦截——因为字符串确实变了。

### 问题 2：修改属性时全量重渲染

**根因链**：

1. 配置面板 onChange → `dispatch(updateFieldConfig(uniqueId, patch))` → `byId[uniqueId]` 变化
2. **DesignerField ②**：`useFieldConf(uniqueId)` 订阅 `byId[uniqueId]`
   - 只有被修改的组件 `byId[id]` 引用变化 → 只有该 DesignerField 重渲染 ✅ 正确
3. **但如果 patch 包含 `config.title`**（我们刚加的优化）：reducer 内同步更新 `components` 树 → `components` 引用变化
   - **DesignerField ④**：每个 DesignerField 都 `useSelector(s => s.designerCanvas.components, shallowEqual)`
   - `components` 引用变了 → 所有 DesignerField 的 selector 返回新引用 → `shallowEqual` 判定不等 → **全部重渲染**
4. **RecursionComponents ①**：也订阅 `components` → `components` 引用变化 → `useMemo` 重算 → 重新递归遍历整棵树 → 所有 `<DesignerField>` 重新创建
   - 虽然 DesignerField 有 `memo + areEqual`，但 `areEqual` 比较 `prevProps.dataSource === nextProps.dataSource`
   - **如果 components 树被 Immer 重建**，`item` 节点引用可能变了（即使内容没变）→ `areEqual` 判定不等 → memo 失效 → 全部重渲染

**结论**：修改属性时全量重渲染的**直接原因**有两个：
- DesignerField ④ 内部订阅了整棵 `components` 树（用于拖拽时读写其他组件）
- `updateFieldConfig` 的 `config.title` 同步路径让 `components` 引用变化，触发所有 DesignerField 重渲染

### 问题 3：ItemField 没有 React.memo

即使 DesignerField 的 memo 拦住了 props 层面的重渲染，一旦 DesignerField 因 `useSelector` 重渲染，其子组件 FieldGenerator → ItemField 都会重渲染（因为 FieldGenerator 和 ItemField 都没有 memo）。

## 三、各组件 memo 情况

| 组件 | React.memo | 说明 |
| --- | --- | --- |
| RecursionComponents | ❌ | 有 `useMemo` 包裹递归逻辑，但组件函数本身每次都会执行 |
| DesignerField | ✅ | `memo(DesignerField, areEqual)`，比较 6 个 props |
| FieldGenerator | ❌ | 普通函数组件 |
| ItemField | ❌ | `widthRenderTask` HOC 包裹，无 memo |
| FieldWrapper | ❌ | 普通 React.FC |
| GroupField | ❌ | `widthRenderTask` HOC 包裹，无 memo |
| LayoutBlock | ❌ | 直接 export |

## 五、优化方案

### 优化 1：ItemField 的 useSelector 改为派生布尔值（高优先级）

**文件**：`src/designer/renderer/components/item-field/index.tsx` L40-46

```ts
// 当前（有问题）：
const { selected, receivedPropsParams } = useSelector(
    (state: any) => ({
        selected: state.component.selected,  // ← 原始字符串，任何选中变化都不同
        receivedPropsParams: state.component.querys.receivedPropsParams,
    }),
    _.isEqual,
);

// 优化后：
const { isSelected, receivedPropsParams } = useSelector(
    (state: any) => ({
        isSelected: state.component.selected === compProps.uniqueId,  // ← 派生布尔值
        receivedPropsParams: state.component.querys.receivedPropsParams,
    }),
    shallowEqual,  // ← 浅比较即可
);
```

**效果**：选中变化时，只有 `isSelected` 从 false→true 或 true→false 的 2 个 ItemField 重渲染，其余全部被 shallowEqual 拦住。

### 优化 2：DesignerField 内部去掉 components 整树订阅（中优先级）

**文件**：`src/designer/renderer/designer-field/index.tsx` L88-89

当前 DesignerField 内部订阅了整棵 `components` 树（用于拖拽 onDragStop 时读写其他组件）。

```ts
// 当前：
const components = useSelector((s: RootReducerState) => s.designerCanvas.components, shallowEqual);
const state = useMemo(() => ({ components }), [components]);
```

拖拽回调中用 `state.components` 读写其他组件。但拖拽是事件回调，不需要响应式订阅。

```ts
// 优化后：拖拽回调中用 store.getState() 同步读
const store = useStore<any>();
// 在 handleOnDragStop 等回调中：
const components = store.getState().designerCanvas.components;
```

**效果**：`updateFieldConfig` 的 `config.title` 同步路径让 `components` 引用变化时，不再触发所有 DesignerField 重渲染。

### 优化 3：ItemField / FieldGenerator 加 React.memo（中优先级）

**文件**：`src/designer/renderer/components/item-field/index.tsx`、`src/designer/renderer/generator.tsx`

当 DesignerField 因 `useFieldConf` 重渲染时，子组件 FieldGenerator → ItemField 不应跟着重渲染（除非 props 变化）。

```ts
// ItemField 导出改为：
export default withModel([useComponentsInfo], ([compsInfo]) => ({
    dpuList: compsInfo.dpuList,
}))(React.memo(widthRenderTask(ItemFieldImp)));
```

**注意**：需要确认 ItemField 的 props 是否稳定（`compProps` 每次都是新对象的话 memo 无效）。

### 优化 4：updateFieldConfig 的 config.title 同步改为仅同步 byId（低优先级）

当前方案：`config.title` 变化时递归更新 components 树 → components 引用变化 → 图层树重渲染。

替代方案：图层树不用 `components` 整树，改用 `useFlatComponents` hook（已存在）按字段订阅每个节点的 `data.config.title`。但这需要重构 DirectoryTree 的数据源，改动较大。

## 六、优先级排序

| 优化 | 难度 | 效果 | 优先级 |
| --- | --- | --- | --- |
| 优化 1：ItemField useSelector 派生布尔值 | 低（改 1 处） | 选中时从 N 次重渲染降到 2 次 | **P0** |
| 优化 2：DesignerField 去掉 components 订阅 | 中（改拖拽回调） | 修改属性时从 N 次降到 1 次 | **P1** |
| 优化 3：ItemField / FieldGenerator 加 memo | 中（需验证 props 稳定性） | 拦截父级重渲染传导 | **P2** |
| 优化 4：图层树改用字段级订阅 | 高（重构 DirectoryTree） | 彻底解耦 components 树 | **P3** |
