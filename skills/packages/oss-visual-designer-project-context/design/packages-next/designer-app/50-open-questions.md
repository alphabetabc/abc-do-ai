## ★ 优先决策（影响协议冻结）

### Q1 · 多选选中态形态（D1/J4）✅ 已拍板（2026-09-17：用户）

- **结论**：扩为 **`string[]`**，新架构必须支持多选。
- 实施要点：扩展落在 **plugins 层**（view 插件 viewUI.selected），非壳层自建；存量大屏 JSON 入口做一次 `split(',')` 转换，逗号串不作为新架构内部契约；getClickSelectedIds（含 FILL_LAYOUT 变体）随 Phase 3 迁移。
- **影响**：多选移动/对齐、图层树 multiple、交互事件 uniqueId 串兼容（入口转换承接）。

### Q2 · 组轮播运行时（B39/C19）✅ 已拍板（2026-09-17：用户）

- **结论**：(a) 协议冻结样式+配置、运行时可换——先兼容，轮播引擎后续可替换。
- **实施要点**：src 现实现基于 react-slick + `React.cloneElement` 向子组件注入 `slider` / `currentGroupSliderActive` props（[group-field/index.jsx](src/designer/renderer/components/group-field/index.jsx) 两分支均如此，原作者注释已标注渲染压力）。新架构**禁止照抄该注入路径**：Phase 3 实现前须先分析子组件状态的数据流方案（候选方向：子组件自行订阅 store，父级不做 props 克隆注入），并结合 440 组件场景验证翻页时重渲染范围。

### Q8 · /schema-designer 独立工具去留（A15）✅ 已拍板（2026-09-17：用户）

- **结论**：(a) 放弃——该独立工具不迁移，配置 schema 由 Phase 2 新解释器生态承接，与 fedx-report 退场方向一致。

### Q5 · 下钻层级（D8）✅ 已拍板（2026-09-17：用户）

## 次优先（Phase 1 前决策）

### Q9 · 场景监控嵌入模式是否抽象为通用「嵌入协议」（A04/B18/D10）✅ 已拍板（2026-09-17：用户）

- **结论**：场景监控作为业务拓展做成**插件**（如 plugin-scene-monitor）注入设计器能力，**优先级非常低**，排在 Phase 1+ 重建主线之后。
- **实施要点**：A04 重建范围按插件形态重新评估（非首批）；其嵌入模式（隐藏区/禁移动/微应用消息保存/物料白名单）是否抽为通用嵌入协议，随插件立项时再定，当前不做特判页面迁移；designer-scene-monitor 注释态子链路（D10）按插件立项时一并核实。

### Q3 · 数字人（A28/C21）、性能监控（C46/B07）是否进首批 ✅ 已拍板（2026-09-17：用户）

- **结论**：均不进首批。
- **数字人**：定位为**能力增强**，探索基于**插件形式**接入（与 Q9 场景监控插件化方向一致），不占 Phase 1-3 主线；插件可行性在立项时验证（meta-human-sdk 外部依赖边界）。
- **性能监控**：**能力保留、不能砍**，后期加——但需在 Phase 3 440 组件性能验收前就位（作为验证工具），届时若插件化方案已成熟可一并走插件。

### Q4 · GlobalFetcher 跨页注入 useInjectGlobalFetcherResponse2nextPage 是否仍有业务场景（C32）✅ 已拍板（2026-09-17：用户）

- **结论**：**放弃该 hook**——业务确认无「页面跳转后子页复用父页数据」场景（实际交互形态为 Modal/Drawer 弹窗，同 store 内，不涉及子页面注入）。
- **实施要点**：GlobalFetcher 主链路（统一请求去重/轮询/过滤消费）照常在 Phase 3 data-fetcher 重建；仅砍 `useInjectGlobalFetcherResponse2nextPage` 及其 Viewer.jsx 挂载点，不迁移。
