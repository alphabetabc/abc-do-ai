## 1. 规划目标与原则

对 src 全量用户可感知能力（差距矩阵 137+ 项）做**终局归属裁定**：每个能力落位到六个承载单元之一，并给出演进路线与依赖关系。

**分配原则**（继承各文档已定调的架构立场）：

1. **core 保持最小**：树状态骨架 + 插件机制 + 纯函数工具层。不感知业务字段语义、不做 UI、不做 undo/redo、不封装物料类型。
2. **插件 = 可复用状态域 + 命令**：跨页面壳可复用、有明确状态拥有权的领域进插件；只服务单一壳层 UI 的不进。
3. **隔离存量，不改造存量**：老物料（antd4/fedx-report 角色 A）封进 MaterialCompatHost；formily 生态锁版本封进 formily-island。退役 = 整包移除。
4. **壳层（designer-app）吸收一切「只在此壳有意义」的能力**：UI、模式矩阵、取数/保存链、hox 替代、具体 data factory。
5. **extra 字段唯一拥有者契约**不变：每个 extra 字段只有一个拥有者插件。

## 4. 归属裁定速查（易争议项的最终裁决）

| 争议项 | 裁决 | 理由 |
| --- | --- | --- |
| 多选选中态 | **view 插件**（string[]），壳层消费 | Q1 已拍板；选中态是跨壳可复用状态域 |
| 模式矩阵三字段 | **壳层 extra slice**，不进 core/plugins | J2；五种 designerType 是壳层路由概念 |
| createRecalcGroupBounds | 算法在 core（纯函数），**接线在 group-management 插件**（派生插件），画布层订阅 | J5 / Q 拍板 |
| copy uniqueId 重置 | layer-management 默认 false，**调用方（画布复制）显式传 true** | J6 |
| 五类 data factory | data-fetcher 插件只留注入位，**实现全部在壳层** | D7 / 20 文档 |
| DPU 链路 | **终局进 dpu 插件**（状态与命令，Phase 3 迁移），Phase 1 先由壳层 hox 替代临时承载；DPU 抽屉 UI 在壳层 | 预览壳与设计壳双消费；待用户确认 |
| ConfigFormatter | **Phase 2 交付**（对齐 40-phases 2-5 与 Phase 2 验收），承载形态（插件 vs 壳层纯函数）立项时按是否需要 extra 状态裁决 | 存量数据反序列化属可复用领域逻辑 |
| 动画 | **建议新 animation 插件**（运行时状态），FieldAnimation 组件在壳层渲染域 | 历史规划既有形态 |
| 性能监控 | 壳层先行（Phase 3 440 验收前），**成熟后插件化** | Q3 |
| 场景监控 | **plugin-scene-monitor**，低优先级 | Q9 |
| 物料列表 / dpuList 等当前 hox 状态 | 壳层域重建（useComponentsInfo 等 hox 五模型替代）；dpuList 若进 dpu 插件则随插件 | C47 |
| useCustomFieldsList 专用 hooks | 现有 core runtime 插件承载状态，**专用 hooks 随删除级联清理在插件层补** | J1 |

## 5. 演进路线（对齐 40-phases，标注归属交付物）

```text
Phase 0  协议冻结（纯文档）
  → 《物料运行时协议.md》七层 + 物料沉淀协议附录（MaterialCompatHost 边界）
  → fedx-report 依赖面审计；样式命名空间规范；拍板结论回写

Phase 1  新壳骨架 + 老物料跑通（可行性证明点）
  → 壳层：脚手架 / core+6 plugins 组装 / 壳层 extra / hox 替代（含 dpuList 临时承载）/ data factory 五类 + DPU 装配注入 / 库导出面与微应用容器对齐
  → MaterialCompatHost：加载链 / 隔离 / 启动预取
  → core：auth 注入位（如采纳）

Phase 2  formily 解释器
  → formily-island：孤岛架构 PoC → SchemaInterpreter → 三件套 shim → 40+ widget 四批
  → config-formatter（对齐 2-5，支撑 Phase 2 验收「存量配置可加载/编辑/保存」）
  →（依赖 Phase 1 壳 + factory 注入）

Phase 3  渲染域重建（工作量最大）
  → 插件增量：view 多选 string[] / group-management 组重算接线 / animation / dpu 插件迁移（从壳层临时态）
  → 壳层：渲染链 / 画布交互 / 六区域 UI / 页面壳全集 / 性能设施 / 440 验收

Phase 4  双轨与退役
  → 灰度切换 / fedx-report 逐角色退场（B→C→A）/ resolve map 条目清理 / 跳板页重建
  →（低优先）plugin-scene-monitor 立项
```

依赖：Phase 0 → 1 → 2/3 部分并行（2 依赖壳 + factory 注入，3-7 六区域 UI 可与 2 并行）→ 4。每 Phase 立项独立 task，Phase 间用户 review 硬门槛。
