## 1. hox vs Redux：域边界原则

历史改造（2026-07-20 ~ 07-28，roadmap task-2026-07-20-003 → task-2026-07-28-004）将**设计器画布域**状态 100% 迁入 Redux：

- 原 useView / useDesigner / Hox 私有 store 的能力 → `designerCanvas` + `viewCanvas` + `viewUI` 三 slice
- 同期迁入：realtimeDataFlow、customFieldsList（task-2026-07-21-011 删除 useDesigner 兼容壳）

留在 hox 的是 **App 壳层域**，5 个 model 全部存活（2026-09-16 grep 验证）：

| model | 职责 | 唯一/主要写入点 |
| --- | --- | --- |
| `src/hox/useLoginInfo.ts` | 登录态、用户信息、designerPermissions | `src/app/container/index.tsx`（登录回调） |
| `src/hox/useEnvironment.ts` | 环境配置（包装 oss-web-common） | createModel 内部（读 localStorage / 远程 config） |
| `src/hox/useAppInfo.ts` | App 容器挂载点、systemInfo | `src/app/container/index.tsx` |
| `src/hox/useComponentsInfo.ts` | 物料库：components 列表 / dpuList / 业务与自定义分组 / componentsMethods | `src/designer/data-query/InitDataQuery/index.tsx`（注意：其 setComponents 是物料列表，与 Redux action setComponents 同名不同物） |
| `src/hox/useDevelopment.ts` | 数据调试：dataDebug / fetchSnapshot | `src/plugins/data-fetcher/DataFetcher.ts` 等 |

> 注意：Redux `app` slice 曾声明过登录态字段，但从未使用已删除（见 `src/store/modules/app.ts` 头注释）——登录态实际由 hox 管。

## 2. 能力域速查

### ①设计器状态域（src/store/modules/）

5 个 slice：`app`（designerType / contextMenu / topToolbarHiddenList）、`component`、`designerCanvas`（components 树 + byId/parentMap 派生索引，**唯一真相源**）、`viewCanvas`（scale/lines/标尺/画布尺寸）、`viewUI`（tabsKey/面板开关）。写走 `dispatch(setComponents / updateFieldConfig / updateViewCanvas ...)`，读走 `useFieldConf(uniqueId)` 等细粒度 hooks。改前必读 `designer-state/`（含已删除 API 禁区）。

### ②画布渲染域（src/designer/renderer/ 等）

渲染链：`generator.tsx` / `GeneratorWidget.tsx` → `designer-parser` → `DesignerField`（含 AlignLine / 拖拽缩放）→ `components/item-field | group-field | layout-block` 分型。操作入口：`canvas-graph`（框选/对齐）、`layer-manager`（copy/delete/group/lock/move/visible）、`common/dnd`（拖放入树）、`aside-panel/layers-tree`（树拖拽 useOnDrop）。性能红线：画布组件必须 React.memo，440 组件场景验收。

### ③物料域（src/designer/materials/ + src/packages/ + src/formily/）

物料加载（materials/index.js + InitDataQuery）→ 渲染（GeneratorWidget → Field，@Packages alias）→ 配置（configuration-panel 的 component/group/page 三级面板，由 formily/widgets 的 30+ schema 组件驱动）。加物料读 `物料开发上下文声明.md`；配 props 读 `物料Props详细配置.md` + `Schema定义工具文档.md`。

### ④交互域（src/plugins/interaction/）

schema 定义在 `formily/widgets/define-interaction-action`，运行时在 `plugins/interaction/component`（hooks + reducer + utils）。配套能力：动画（`plugins/animation`）、配置格式化（`plugins/config-formatter`）。下钻/派发模式见 `下钻与派发逻辑总结.md`。

### ⑤数据域（src/plugins/data-fetcher/）

`DataFetcher` 按 dataType 分流（api / dpu / dataset / json），`GlobalDataFetcher` + `GlobalDataSet` 管全局数据集，`RealtimeDataFlow` 做组件间数据流转（状态在 Redux）。调试快照（fetchSnapshot）走 hox useDevelopment，由 `renderer/components/data-debug` 消费。⚠️ 无契约文档。

### ⑥App 壳层域（src/app/ + src/hox/ + src/routes/ + src/pages/）

`app/container` 是微前端挂载入口（登录回调写入 hox），`app/initializer` 初始化，`routes/` 路由，`pages/` 设计器页 / 预览页（large-screen Viewer、material）等。`common/services` 是后端 API 层（visualManage / snapshot / material / dpu / dataset / compManage），依赖 hox useEnvironment 取环境。
