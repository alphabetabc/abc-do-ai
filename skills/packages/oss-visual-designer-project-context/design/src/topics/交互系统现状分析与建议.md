# 交互系统现状分析与建议报告

## 1. 概述

本文档基于对项目代码的分析，总结视觉设计器中**交互（Interaction）系统**的架构设计、代码组织现状及改进建议。

项目中的交互系统主要包含两大核心功能：
- **下钻（Drill-down）**：点击数据项时，打开 Modal 或 Drawer 弹窗展示详情
- **派发（Dispatch）**：点击时，将数据作为参数派发给其他组件或变量

---

## 2. 交互系统架构

### 2.1 整体架构图

```
用户点击事件
     │
     ▼
┌─────────────────────────────────────────────────────┐
│  物料组件 (使用 interaction.dispatch 派发)             │
│  - Table、Chart、StatsIndi 等                        │
└─────────────────────────────────────────────────────┘
     │
     ▼ dispatch({ data: [{ fieldName, state }] })
     │
┌─────────────────────────────────────────────────────┐
│  Redux Store (component/interactions)               │
│  - reducer 处理状态更新                              │
│  - 维护组件间交互状态                                │
└─────────────────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────────────────┐
│  订阅组件 (使用 interaction.subscribe 获取)           │
│  - 变量组件、下钻容器等                              │
└─────────────────────────────────────────────────────┘
```

### 2.2 核心模块分布

| 层级 | 路径 | 职责 |
|------|------|------|
| **常量定义** | `packages/share/src/interactions/` | 定义 action/event/drill-down 常量 |
| **业务逻辑** | `src/plugins/interaction/component/` | Hooks、Reducer、工具函数 |
| **配置 UI** | `src/formily/widgets/define-interaction-action/` | 设计器中可视化配置交互 |
| **使用方** | `src/packages/*/` | 各物料组件使用交互能力 |

#### 3.2.1 核心 Hook（hooks.ts）

```typescript
// 1. 预处理交互参数，用于数据请求
useInteractionsPreprocessor

// 2. 创建交互对象 API（派发/订阅/获取配置）
useCreateInteractionApi

// 3. 获取组件间交互图谱关系
useInteractionsGraph

// 4. 获取当前下钻数据
useCurrentFieldDrilldownData

// 5. 获取订阅的值对象
useSubscribeObject
```

#### 3.2.2 交互类型定义（interface.ts）

```typescript
interface InteractionType {
    dispatch: (args: { type?: string; data: Array<{ fieldName: string; state: any }> }) => void;
    subscribe: any;        // 当前组件订阅的数据
    defined: Record<string, any>;  // 定义联动字段集合
    action: any;          // 当前组件派发出去的数据
}

interface InteractionEvent {
    fieldName: string | number | null;  // 事件ID
    uniqueId: string | number | null;   // 事件源
    state: any;                          // 状态数据
    time: any;                          // 事件时间
    // CloudEvents 协议字段（部分未使用）
    specVersion?: string | null;
    type?: string | null;
    dataContentType?: string;
    dataSchema?: any;
    data?: any;
}
```

## 4. 下钻与派发机制

### 4.1 交互类型常量

**文件**：`src/common/constants/interactions.ts`

| 常量名 | 值 | 说明 |
|--------|-----|------|
| `INTERACTION_TYPE_CELL` | `'Dispatch'` | 单元格级别派发 |
| `INTERACTION_TYPE_ROW` | `'RowDispatch'` | 行级别派发 |
| `INTERACTION_TYPE_MODAL` | `'Modal'` | 下钻打开 Modal |
| `INTERACTION_TYPE_DRAWER` | `'Drawer'` | 下钻打开 Drawer |
| `INTERACTION_TYPE_CheckBoxCELL` | `'CheckBoxDispatch'` | 复选框单元格派发 |

### 4.2 配置结构

#### 下钻配置（configurableEvent）
```
configurableEvent.drilldownEvent
├── show: boolean          // 是否开启下钻
├── effect: 'Modal'/'Drawer' // 事件效果
├── params: string          // URL 参数
├── title: string           // 弹窗标题（Drawer）
├── placement: string       // 位置（Drawer）
├── width/height: number    // 尺寸
├── mask: boolean           // 遮罩
└── closable: boolean       // 关闭按钮
```

#### 动态事件配置（dynamicEvents）
```
dynamicEvents[]
├── clickKey: string       // 点击的键
├── effect: 'Dispatch'/'Modal'/'Drawer'/'RowDispatch'/'CheckBoxDispatch'
└── actionField: string    // 动作字段
```

### 4.3 处理流程

```
用户点击
    │
    ▼
检查 interaction?.defined
    │
    ├─ 否 → 无响应
    │
    └─ 是
        │
        ▼
    检查下钻事件 (configurableEvent.drilldownEvent.show)
        │
        ├─ 是 + effect 为 Modal/Drawer
        │       │
        │       ▼
        │   dispatch({ fieldName: 'drilldownEvent', state: { visible: true, ...data } })
        │       │
        │       ▼
        │   打开 Modal/Drawer
        │
        └─ 否 → 检查动态事件 (dynamicEvents)
                    │
                    ▼
                匹配 clickKey
                    │
                    ▼
                dispatch({ fieldName: 'DynamicEvent-xxx', state: data })
```

## 6. 问题分析与评分

### 6.1 问题清单

| # | 问题 | 严重程度 | 说明 |
|---|------|----------|------|
| 1 | **命名混乱** | 中 | `action`/`event`/`interaction` 混用，如 `ACTION_INTERACTION` vs `DYNAMIC_EVENTS` |
| 2 | **概念模糊** | 中 | `fieldName` 既表示事件 ID 又表示字段名，语义不清 |
| 3 | **Hook 职责过重** | 中 | `hooks.ts` 中 5 个 Hook 各有不同职责，应拆分 |
| 4 | **CloudEvents 设计不完整** | 低 | `interface.ts` 中有 TODO 注释，部分字段未使用 |
| 5 | **历史包袱** | 低 | `DEPRECATED_FIELD_NAME_DRILL_DOWN` 等废弃字段仍存在 |
| 6 | **文档缺失** | 高 | 仅有本项目这一份总结文档 |

### 6.2 评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 代码组织 | 6/10 | 分散但有规律 |
| 命名规范 | 5/10 | action/event/interaction 混用 |
| 职责划分 | 5/10 | Hook 过于臃肿 |
| 可维护性 | 6/10 | 有一定耦合但可接受 |
| 文档完备 | 3/10 | 基本没有文档 |

## 7. 改进建议

### 7.1 统一概念模型

建议统一命名：

| 当前 | 建议 |
|------|------|
| `ACTION_INTERACTION` | `UPDATE_INTERACTION_STATE` |
| `DYNAMIC_EVENTS` | `DYNAMIC_ACTIONS` |
| `CONFIGURABLE_EVENT` | `CONFIGURABLE_ACTION` |
| `fieldName`（事件标识） | `eventId` |

### 7.2 拆分 Hooks

将 `hooks.ts` 拆分为独立文件：

```
src/plugins/interaction/component/
├── hooks/
│   ├── useInteractionDispatcher.ts   // 派发交互
│   ├── useInteractionSubscriber.ts   // 订阅交互
│   ├── useInteractionGraphBuilder.ts // 构建图谱
│   ├── useDrillDownHandler.ts        // 下钻处理
│   └── useInteractionPreprocessor.ts // 参数预处理
```

### 7.3 清理废弃代码

- 删除 `DEPRECATED_FIELD_NAME_DRILL_DOWN`
- 移除 reducer 中注释掉的代码
- 补充 CloudEvents 字段或移除未使用的

### 7.4 建立文档体系

建议创建以下文档：

| 文档 | 内容 |
|------|------|
| `交互系统设计.md` | 整体架构、核心概念 |

## 8. 总结

项目的交互系统核心思路清晰：
- **Redux 统一状态管理** ✓
- **发布-订阅模式** ✓
- **配置与实现分离** ✓

但存在**命名不统一**、**职责边界模糊**、**历史包袱积累**等问题。建议：
1. **短期**：清理废弃代码，统一命名规范
2. **中期**：拆分臃肿的 Hook，建立文档
3. **长期**：重构类型定义，补全 CloudEvents 设计
