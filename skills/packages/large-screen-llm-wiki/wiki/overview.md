# 大屏自然语言生成（NL→DSL）· Wiki 总览

> 本目录是"大屏 + AI"方向的统一输出窗口：对外是按模板提交的工作计划与产出，对内是个人可带走的规则资产积累。
> 原则：**所有内容组件无关、项目无关**——不出现具体项目名称、业务概念、真实页面截图与数据。

## 目录结构（Wiki 骨架）

```
large-screen-llm-wiki/
├── SKILL.md              # skill 入口：定位、约束、文件索引
├── draft-plan.md         # 工作计划（提交版，含任务表）
├── wiki/                 # 知识沉淀输出窗口
│   ├── overview.md       # 本文件：总览与索引
│   ├── 01-schema/        # Schema 规范（widget 类型/布局/联动/数据绑定）
│   ├── 02-translation/   # 自然语言 → Schema：prompt 模板、few-shot、校验与纠错规则
│   ├── 03-adapter/       # 适配层规范：抽象类型 → 任意组件库的映射约定（本层才允许出现具体技术，但不出现具体项目）
│   ├── 04-cases/         # 生成案例库：成功案例、失败案例、踩坑与纠错经验
│   └── 05-sop/           # SOP 与复用指引：换项目/换组件库的迁移步骤
```

## 分层职责（通用性边界）

| 层          | 位置                   | 通用性                                         |
| :---------- | :--------------------- | :--------------------------------------------- |
| Schema 规范 | `01-schema/`           | 完全通用，零项目/组件概念                      |
| 翻译规则    | `02-translation/`      | 完全通用，prompt 与校验不绑定任何实现          |
| 适配层规范  | `03-adapter/`          | 半通用：允许提到具体组件技术，禁止提到具体项目 |
| 案例与 SOP  | `04-cases/`、`05-sop/` | 案例用虚构/脱敏场景，SOP 面向任意项目复用      |

## 写作纪律（所有 wiki 内容适用）

1. 不出现项目名称、业务线、真实客户/业务数据、真实页面截图
2. 示例场景一律虚构（如"某市运行监控大屏"），字段名用通用词（region / metric / trend）
3. 涉及现有工程实践的，只说"现有大屏工程"，不指名是哪个
4. 每篇文档结尾标"可带走等级"：`A=纯通用资产` / `B=含技术细节需小改可复用` / `C=仅本项目`
