# T1.4 适配层规范设计与打通验证

> 计划窗口：11.07 – 11.10 | 依赖：T1.3 完成 | 状态：未开始

## 目标

写适配层规范（抽象类型 → 本项目组件的映射约定），并用 1 个类型做最小打通验证，证明"上面两层不知道下面是谁"成立。

## 输入

| 输入 | 位置 | 说明 |
| :--- | :--- | :--- |
| Schema v1 完整定义 | `wiki/01-schema/schema-v1.ts` | 被映射的源结构 |
| 组件能力清单 | `wiki/03-adapter/inventory/component-capabilities.md` | 映射目标的能力事实 |
| API 签名表 | `wiki/03-adapter/inventory/api-signatures.md` | 对接 registerWidget / createLargeScreen 的方式 |

## 步骤

1. 写映射约定：每个抽象类型的属性 → 组件 props 的转换规则、缺省策略、不支持属性的降级策略
2. 定义 adapter 接口形状（输入 Schema 节点，输出注册/渲染所需结构）
3. 最小打通：选 1 个类型（建议 chart-bar 或 kpi-card）实现映射函数，把一段 Schema JSON 渲染到现有组件
4. 记录接口不匹配点，回填规范

## 输出

| 产物 | 落盘位置 | 内容要求 |
| :--- | :--- | :--- |
| 适配层规范 | `wiki/03-adapter/adapter-spec.md` | 映射约定 + adapter 接口 + 降级策略（等级 B） |
| 打通验证记录 | `wiki/03-adapter/adapter-poc.md` | 验证代码位置、Schema 输入、渲染结果描述、遇到的不匹配点 |

验证代码本身放工程内合适位置（不强制入 wiki），记录里写清路径。

## 验收

- [ ] 1 个抽象类型端到端渲染成功（Schema JSON → 现有组件出现在页面上）
- [ ] 不匹配点全部记录并有处理策略（转换 / 降级 / 暂不支持）
- [ ] 规范中明确"换组件库时只需重写本层"的边界说明
- [ ] 阶段一整体完成，素材进第三次周同步（~11.11）
