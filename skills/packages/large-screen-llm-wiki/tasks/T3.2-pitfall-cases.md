# T3.2 踩坑与规则沉淀

> 计划窗口：12.15 – 12.24 | 依赖：T3.1 完成 | 状态：未开始

## 目标

汇总全周期的失败案例、纠错经验与使用边界，形成"这套东西什么时候好用、什么时候不好用"的诚实结论。**验收口径即"输出 skill"。**

## 输入

| 输入 | 位置 | 说明 |
| :--- | :--- | :--- |
| 失败案例集 | `wiki/04-cases/failure-cases.md` | T2.3 起积累 |
| 冒烟/回归测试记录 | `wiki/02-translation/smoke-test-notes.md` 等 | 早期偏差 |
| 场景模板验证记录 | `wiki/01-schema/layout-patterns.md` | 边界扩展后的新发现 |
| 周同步记录（个人留档） | — | 各阶段暴露的问题 |

## 步骤

1. 归类失败案例：翻译层（LLM 理解偏差）/ 结构层（Schema 表达不了）/ 渲染层（适配缺失），每类给规律总结
2. 沉淀纠错经验：哪类错误重试有效、哪类必须改 prompt、哪类是 Schema 设计问题
3. 写使用边界：当前链路支持什么、明确不支持什么、扩展成本在哪
4. 把可执行的规则回写到 prompt 模板 / 校验规则（形成闭环，不只是记录）

## 输出

| 产物 | 落盘位置 | 内容要求 |
| :--- | :--- | :--- |
| 踩坑与经验总结 | `wiki/04-cases/pitfalls-and-lessons.md` | 分类案例 + 规律 + 纠错策略（等级 A/B） |
| 使用边界说明 | `wiki/04-cases/scope-and-limits.md` | 支持面 / 不支持面 / 扩展成本（等级 A） |
| 规则回写 | 更新 `02-translation/` 相应文档 | 经验落回可执行资产 |

## 验收

- [ ] 失败案例全部归类且有规律总结（不是流水账）
- [ ] 使用边界诚实明确（含"不支持什么"——这是可信度的来源）
- [ ] 至少 2 条经验回写进了 prompt 模板或校验规则
- [ ] 素材进周同步（~12.24）
