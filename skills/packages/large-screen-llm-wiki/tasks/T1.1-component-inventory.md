## 已验证事实（2026-10-23，源自真实代码 Read）

以下事实已核对源码，执行时直接使用，避免凭假设输出不稳定：

### 注册机制（`web/components/large-screen/utils.ts`）

- `createLargeScreen(screenName)` 返回 `{ registerWidget, getWidgets, defineInteractionFields, internalFields, internalDispatcher, screenName, deleteScreen }`
- `registerWidget(opts)` 完整参数：**`{ name, element, layout, style?, group?, animateCss?, subscribe? }`**（不止 5 个字段，`style` 和 `animateCss` 常被遗漏）
- `layout` 为绝对定位 `{ left, top, width, height, zIndex? }`，**有默认值 400×300 @ (0,0)**，部分传入可覆盖
- 内部自动生成：widget id（含计数器）、`groupFilterId`（由 `group ?? 'default'` 派生的混淆字符串）
- `TWidget` 类型（utils.ts L5-23）：含 `screen / widgetName / element / id / groupFilterId / layout / style? / control.subscribe? / animateCss`

### 联动机制

- **内置字段共 6 个**（不止 2 个）：`widgetVisible`、`widgetGroup:visibleFilter`、`global`、`highlight`、`downplay`、`enableControl`
- `defineInteractionFields(fields)` 与内置字段重名会 **throw Error**（重要约束）
- `widgetGroup:visibleFilter` 派发数据**必须是数组**（`internalDispatcher` 内部强制 `[data]` 包装）
- 订阅分两条通道：`useWidgetInteractionContext`（同屏 Event EventEmitter）+ `useScreenControlSocketContext`（Socket，受控模式）；内置字段更新走 `widgetSubscribe` state，自定义字段走 `elementSubscribe` 并以 **key（字段别名）注入 widget element 的 props**
- `dispatch(field, data, extra?)`：`extra.disableControl` 可跳过 Socket 只走本屏 emit

### 渲染层（`Widget.tsx` / `WidgetsRender.tsx`）

- `WidgetsRender({ getWidgets })` 包一层 `WidgetInteraction`（Context + EventEmitter）
- `Widget` 组件：绝对定位 section，`widgetVisible` 控制 display/opacity；`enableControl`（Socket 受控开关）经 URL/常量控制
- widget element 收到的注入 props：`{...elementSubscribe}` + `enableControl` + `dispatch`

### 黑盒边界（重要）

- `defineFields` 的真身在 `lib/rc-large-screen.min.js`（**打包产物，源码不在本仓库**）。追到 `defineFields(field).getField(name)` 行为即停，按黑盒记录，**不得编造其内部实现**
- `useScreenControlSocketContext` 来自 `../socket`，盘点时需补读该文件
