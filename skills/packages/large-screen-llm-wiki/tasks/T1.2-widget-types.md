# T1.2 抽象 widget 类型定义

> 计划窗口：11.01 – 11.07 | 依赖：T1.1 完成 | 状态：未开始

## 目标

定义 Schema v1 核心：6–8 个组件无关的抽象 widget 类型及属性，纯结构定义，不含本项目概念。

## 已验证锚点（2026-10-23 预验证，源自 T1.1 前置代码 Read）

- 现有体系的 widget 概念含 7 个注册参数维度：name / element / layout(绝对定位，含默认值) / style / group / animateCss / subscribe——抽象类型设计须能承载后 5 个维度（element 由类型决定、name 由实例决定）
- widget 可见性由订阅 `widgetVisible` / `widgetGroup:visibleFilter`（数组）驱动，类型属性中需预留 visibility 相关表达
- `enableControl`（外部受控开关）是运行时注入 prop，**不属于** Schema 静态结构，注意区分
- echarts 生态组件远多于 8 类（pie-3d / gauge / bar3d-line / horizontal-interval-bar-chart / digital-flop / ind-top-n…）：**抽象类型只收编高频共性类，其余以"扩展类型清单"附录形式记录、不进 v1**，防止为凑数硬合并

## 步骤

1. 从能力清单归纳类型：每个候选抽象类型标注"由哪些真实组件支撑、合并了什么共性"
2. 逐类型定义属性：必选 / 可选 / 类型 / 取值约束 / 默认值
3. 设计顶层结构骨架：`{ widgets[], 布局容器, 全局配置 }`
4. 每类写一个虚构示例 JSON（场景虚构，字段通用词 region / metric / trend）
5. 通用性自查 + 落盘

## 验收

- [ ] 每个类型的每个属性都能追溯到能力清单里的真实组件能力（无凭空属性）

- [ ] 示例 JSON 可被人读懂且字段全部通用词
