# T1.3 布局 / 联动 / 数据绑定规范

> 计划窗口：11.07 – 11.10 | 依赖：T1.2 完成 | 状态：未开始

## 目标

补全 Schema v1：布局（位置/尺寸/分组）、联动（字段派发/订阅）、数据绑定（来源/映射）的结构定义，并合并为完整 Schema v1。

## 已验证锚点（2026-10-23 预验证，源自真实代码 Read）

- **内置字段是 6 个不是 2 个**：`widgetVisible` / `widgetGroup:visibleFilter` / `global` / `highlight` / `downplay` / `enableControl`。联动规范须能表达前 5 个的语义（enableControl 属运行时控制，可排除出 Schema）
- **数组约束**：`widgetGroup:visibleFilter` 派发数据必须是数组；且默认 group 'default' 恒可见——通用化时注意这个"默认组兜底"语义
- **字段重名保护**：自定义字段与内置字段重名会 throw——Schema 层需定义"保留字清单"机制，翻译层校验也要查
- **订阅是别名映射**：subscribe 配置为 `{ 别名key: field }`，派发命中后按别名注入 props——通用化的联动规范需保留"事件名 → 注入 prop 名"的解耦设计，这是现有机制最有价值的抽象点
- **双通道**（同屏 EventEmitter / Socket 受控）：Schema 层只描述"什么联动"，通道选择属适配层运行时职责，不进 Schema

## 步骤

1. 布局规范：位置 / 尺寸 / 分组 / 层级的结构定义与约束（越界规则留给 T2.2 校验器）
2. 联动规范：事件源 / 派发字段 / 订阅条件 / 目标更新的结构定义；语义对齐现有机制，命名通用化
3. 数据绑定规范：来源类型（静态 / 接口 / 订阅）、字段映射、刷新方式
4. 合并为完整 Schema v1（TS 类型定义或 JSON Schema）
5. 用 T1.1 的页面反查记录做回放验证：真实页面的布局/联动能用新规范表达（文字推演即可）
