## 1. 模块概述

地图模块是 cmd-dispatcher 大屏的核心交互区域，承载 7 层级下钻、绘制框选、区域详情弹窗三大能力。

**不引入** OpenLayers / fedx-gis / d3 / 任何地图库——地图形态为静态图片 + SVG overlay。

### 文件组织

```
web/pages/bj-cmcc-cmd-dispatcher/modules/map/
├── index.tsx                # 组装入口（MapStage + MapToolbarSvg + MapLegend）
├── map-stage.tsx            # 底图 + 轮廓 + SVG overlay + 打点 + 弹窗
├── map-toolbar-svg.tsx      # SVG 设计稿工具栏（select/rect/circle/polygon + 删除）
├── map-toolbar.tsx          # 旧版按钮工具栏（保留，未使用）
├── map-legend.tsx           # 图例（独立 memo 组件）
├── map-detail-modal.tsx     # 框选区域详情弹窗
├── shape-renderer.tsx       # SVG shape 渲染器（rect/circle/polygon）
├── use-draw.ts              # 鼠标绘制交互 hook
├── presets.ts               # 常量映射（资源/层级/轮廓位置/图例/打点 icon）
└── types.ts                 # Shape / Tool / DrawState / MapMarker 类型
```

## 2. 层级体系（七层）

### 2.1 概述

地图模块采用 **7 级下钻**结构，由 store 持有 `currentLevel: Level`，通过 `NEXT_LEVEL` / `PREV_LEVEL` 映射驱动层级切换。所有层级共享一套渲染管线（底图 + outline + 打点 + SVG overlay），差异仅在资源路径 / 数据源 / 可见模块 / mock 文件。

### 2.2 枚举与渲染角色

```ts
// store/index.ts
export type Level =
    | 'city'        // L1 北京 · 全网
    | 'company'     // L2 分公司
    | 'district'    // L3 行政区
    | 'street'      // L4 街道
    | 'community'   // L5 社区
    | 'station'     // 物理站
    | 'logical';    // 逻辑站
```

-   store 初始 `currentLevel = 'city'`（参见 [003-frontend.md §7](../../003-frontend.md)）
-   常量定义：[`presets.ts#L103-L122`](web/pages/bj-cmcc-cmd-dispatcher/modules/map/presets.ts#L103-L122)（`NEXT_LEVEL` / `PREV_LEVEL`）
-   PM §L3 明确：cell 层已合并到 community，**没有独立的 NR/Cell 层**

### 2.3 七层概览（一张总表）

| #     | Level (`type`) | 中文       | 业务实体       | 数据来源（PM 链路）                        | 节点打点                | 资源打点          | 可见模块组 | 静态资源目录                  |
| ----- | -------------- | ---------- | -------------- | ------------------------------------------ | ----------------------- | ----------------- | ---------- | ----------------------------- |
| **L1** | `city`        | 北京       | 北京移动全市   | PM §2.3 合计行（全网编制）                  | 4 分公司                | **6 类资源** × 32 | A 组       | `map/city/`                   |
| **L2** | `company`     | 分公司     | 城区三分公司 ◄ | L1 下属行政区清单 + §2.3 城区三行           | 2 行政区                | **6 类资源** × 28 | A 组       | `map/company/`                |
| **L3** | `district`    | 行政区     | 石景山区 ◄     | L2 下属街道清单 + L2 画像                   | 8 街道                  | **6 类资源** × 12 | A 组       | `map/district/`               |
| **L4** | `street`      | 街道       | 广宁街道 ◄     | L3 下属社区清单 + §L3 物理站清单 + 资源清单 | 5 社区 + 7 物理站（td/nr） | **6 类资源** × 7 完整 PM 数据 | A 组       | `map/street/`                 |
| **L5** | `community`   | 社区       | 东山社区 ◄     | L4 下属物理站清单 + §关联性说明 3           | 2 物理站（td/nr）       | **6 类资源** × 6  | B 组       | `map/community/`              |
| —     | `station`     | 物理站     | 物理站粒度     | 现有 `map-markers.json` station key        | 3 物理站（保留现有）    | —                 | C 组       | `map/station/`（含 sub-td/nr） |
| —     | `logical`     | 逻辑站     | 逻辑站粒度     | 现有 `map-markers.json` logical key         | 1 逻辑站（保留）        | —（特殊 `icon: "radar"`） | D 组       | `map/logical/`                |

> **◄ 标记**：表示当前 demo 选定的"主下钻链路"上的目标节点（城区三分公司 → 石景山 → 广宁 → 东山）。
> **粗体**：表示前五层（city~community）有"6 类资源打点"，后两层（station/logical）只有节点打点。

### 2.4 前后两段的分界（L5 community / station / logical）

-   **前五层（city~community）**：A/B 组模块可见；打点 = 节点（高优先级地理单元）+ 6 类资源打点（见 §10）；timeline 可影响（前三层 city/company/district，见 §8）
-   **后两层（station / logical）**：C/D 组模块可见；打点 = 节点 only，无资源打点；timeline 不响应；station 层节点带 `subType: 'td' / 'nr'`；logical 层节点走 `icon: 'radar'` 特殊路径

> **设计取舍**：第六层做物理/逻辑拆分是因为 PM §L3 明确"小区清单 vs 站址画像 vs 站址性能" 三类指标都要呈现（见 [001-pm-output.md](../../001-pm-output.md)），物理站粒度承载"基础设施指标"，逻辑站粒度承载"服务化指标"。

### 2.5 层级切换交互

-   点击 outline `<img>` → 下钻下一层（`NEXT_LEVEL` 映射）
-   点击 base `<img>` → 返回上一层（`PREV_LEVEL` 映射）
-   city 层 base 不可点击（无上一层）；logical 层 outline 不可点击（无下一层）
-   仅 `activeTool === null`（无工具激活）时底图/轮廓可点击；有工具激活时 `pointerEvents: 'none'`，由 SVG overlay 接管

### 2.6 crossfade 过渡动画

层级切换时旧层淡出 + 新层淡入同步进行：

-   `prevSnapshot` 快照机制：旧层保留 500ms 供淡出
-   `map-crossfade-in`：opacity 0→1 + scale 1.03→1
-   `map-crossfade-out`：opacity 1→0 + scale 1→0.97
-   过渡期间新层 z-index 临时提升到 11/12

## 3. 渲染架构

### 3.1 z-order

| 层           | 内容                 | z-index |
| ------------ | -------------------- | ------- |
| 详情弹窗     | `MapDetailModal`     | 10      |
| 图例         | `MapLegend`          | 16      |
| 工具栏       | `MapToolbarSvg`      | 17      |
| 打点         | marker `<img>`       | 5       |
| SVG overlay  | `<svg>` shape 绘制层 | 3       |
| 轮廓         | outline `<img>`      | 2       |
| 底图         | base `<img>`         | 1       |
| 地图 wrapper | `cmd-dispatcher-map` | 0       |

### 3.2 SVG overlay

-   `viewBox="0 0 2880 1080"`，`preserveAspectRatio="none"`
-   仅 `activeTool !== null` 时渲染（有工具激活时才显示）
-   `pointerEvents: 'auto'`，接收所有鼠标事件

### 3.3 坐标系

设计稿像素系（2880×1080），不引入投影。鼠标事件坐标转换：

```ts
const toDesignCoord = (e: React.MouseEvent) => {
    const rect = svg.getBoundingClientRect();
    return {
        x: ((e.clientX - rect.left) / rect.width) * 2880,
        y: ((e.clientY - rect.top) / rect.height) * 1080,
    };
};
```

### 3.4 静态资源

```
public/static/images/bj-cmcc-cmd-dispatcher/map/
├── city/        base.png + outline.png + 0.png(绿) + 1.png(红)
├── company/     同上
├── district/    同上

├── community/   同上
```

-   `base.png`：底图背景，填满 2880×1080
-   `outline.png`：轮廓叠加层，按 `OUTLINE_POSITION` 表的 `left/top` 定位
-   `0.png` / `1.png`：打点 icon（绿色正常 / 红色告警）
-   `sub-td.png` / `sub-nr.png`：station 层 subType 专属 icon

### 3.5 打点（marker）

#### 3.5.1 数据双源

地图打点有 **两套数据源**，按层级和 timeline 状态切换：

| 数据源                          | 适用层级                         | 选择条件                                |
| -------------------------------- | -------------------------------- | --------------------------------------- |
| `public/static/mock/.../map-markers.json` | 全 7 层级，作为默认 / fallback        | street/community/station/logical 始终走这里；timeline 在非有效层也不影响 |
| `public/static/mock/.../history-timeline.json` | **仅 city/company/district** 三层 | 当 `currentLevel ∈ EFFECTIVE_LEVELS` 时，按 `currentTimeIndex` 取当前时间点的 `markers` |

详见 §8 时间轴历史回溯的"有效层级"概念。

#### 3.5.2 marker 类型与 icon 规则

`MapMarker` 类型定义（[`types.ts#L36-L49`](web/pages/bj-cmcc-cmd-dispatcher/modules/map/types.ts#L36-L49)）：

```ts
interface MapMarker {
    left: number;          // 设计稿像素坐标（绝对像素，base.png 2880×1080 系）
    top: number;           // 设计稿像素坐标
    status: 0 | 1;         // 0=绿（正常）、1=红（告警/退服）
    type: string;          // 当前层级名：city / company / district / street / community / station / logical
    subType?: string;      // 可选：emergency-vehicle / repair-vehicle / generator / sat-bag / wireless-team / transmission-team / td / nr
    icon?: string;         // 特殊 icon（如 'radar'），覆盖 subType/status 路径
    category?: string;     // 图例 checkbox label（用于 §9 过滤）
    width?: number;        // 覆盖默认宽度（logical 雷达）
    height?: number;
    opacity?: number;
    rotate?: number;
}
```

`getMarkerIcon(level, marker)` 决策顺序（[`presets.ts#L17-L22`](web/pages/bj-cmcc-cmd-dispatcher/modules/map/presets.ts#L17-L22)）：

```ts
if (marker.subType) → `map/${level}/sub-${marker.subType}.png`   // 资源专属 icon
if (marker.icon === 'radar') → `icon-radar.svg`                    // logical 雷达
else → `map/${level}/${marker.status}.png`                         // 绿/红兜底
```

#### 3.5.3 渲染细节

-   `useRequest<MarkerData>` fetch + 按 `currentLevel` 过滤（对 fallback 路径）
-   打点延迟渐显：`0.15 + idx * 0.04s`
-   legend-1 层级（city~community）的打点额外按 `legendCheckedValues` 过滤 `marker.category`（详见 §9）
-   status=0 不闪烁（user 2026-08-25 决策：仅 status=1 闪烁，与 PM 设计稿对齐"红色 = 待办告警需注意"）

## 4. 绘制交互

### 4.1 事件路由

SVG 容器统一接管 mousedown / mousemove / mouseup / click / dblclick，通过 `activeTool` 分发：

| 工具      | 事件                                | 行为                    |
| --------- | ----------------------------------- | ----------------------- |
| `select`  | click shape                         | 选中 shape + 弹窗       |
| `select`  | click 空白                          | 取消选中 + 关闭弹窗     |
| `rect`    | mousedown→move→up                   | 拖拽创建矩形            |
| `circle`  | mousedown→move→up                   | 拖拽创建圆（起点=圆心） |
| `polygon` | click 落点 → dblclick 收尾（≥3 点） | 创建多边形              |

### 4.2 DrawState 自管

临时绘制态由 `use-draw` hook 内部 `useState` 管理，不入 store。仅在 mouseup / dblclick 收尾时调 `addShape` 落入 store。

hook 返回 `previewShape` 供 `<MapStage>` 渲染临时预览。

### 4.3 Shape 类型

```ts
export type Shape =
    | { id: string; type: 'rect'; x: number; y: number; w: number; h: number }
    | { id: string; type: 'circle'; cx: number; cy: number; r: number }
    | { id: string; type: 'polygon'; points: Array<{ x: number; y: number }> };
```

### 4.4 ShapeRenderer

| prop          | 类型                            | 说明                                         |
| ------------- | ------------------------------- | -------------------------------------------- |
| `shape`       | `Shape`                         | 渲染数据                                     |
| `selected`    | `boolean`                       | 选中态高亮（橙色 `#ff8800` + strokeWidth=3） |
| `preview`     | `boolean`                       | 绘制中预览（黄色虚线 `#ffff00`）             |
| `interactive` | `boolean`                       | select 模式下 shape 可接收 click 命中        |
| `onSelect`    | `(e: React.MouseEvent) => void` | 点击回调，内部 `stopPropagation`             |

### 4.5 工具栏（MapToolbarSvg）

基于 `tools.svg` 转换的 SVG 设计稿工具栏：

-   六边形 = select，矩形/圆形/多边形 = 对应绘制工具
-   active 工具高亮：叠加半透明青色蒙版
-   **toggle 逻辑**：再次点击已高亮工具 → `clearShapes()` + `setModalOpen(false)` + `setTool(null)`
-   透明 rect 覆盖区域作为点击热区
-   select 模式 + 有选中 shape 时显示"🗑 删除"按钮

### 4.6 SVG overlay 显隐

-   `activeTool === null`（初始/无高亮）→ SVG overlay 不渲染，底图/轮廓可点击层级切换
-   `activeTool !== null`（有工具激活）→ SVG overlay 渲染，底图/轮廓 `pointerEvents: 'none'`

### 4.7 防误触

-   拖拽距离 ≤ 2px 不创建 shape
-   polygon dblclick 前 300ms 内的第二次 click 被过滤（避免多追加重复顶点）
-   polygon `onPointerUp` 不重置 DrawState（仅 rect/circle 在 pointerup 重置）

### 4.8 绘制后自动弹窗

绘制完 shape 后自动选中 + 弹窗（无需切 select 手动点击）：

-   rect/circle：`onPointerUp` 落定后 → `setSelected(id)` + `setModalOpen(true)`
-   polygon：`onDoubleClick` 收尾后 → `setSelected(id)` + `setModalOpen(true)`

## 5. 框选区域详情弹窗

### 5.1 弹窗触发

-   绘制完 shape 自动弹出（§4.8）
-   select 模式下点击 shape 选中 → `setModalOpen(true)`
-   点击空白处 → `setModalOpen(false)`
-   toggleTool 取消高亮 → `clearShapes()` + `setModalOpen(false)`
-   删除选中 → `setModalOpen(false)`
-   弹窗关闭按钮 → `setModalOpen(false)`

### 5.2 层级约束

仅 `currentLevel === 'street'` 时弹窗可见。其它层级框选 shape 不弹窗。

### 5.3 智能避让

弹窗根据选中 shape 的中心 X 坐标（设计稿像素系 2880×1080）自动选择弹出方向：

-   shape 中心在左半区（x < 1440）→ 弹窗在右侧
-   shape 中心在右半区（x ≥ 1440）→ 弹窗在左侧
-   弹窗不遮挡选中的 shape 边界

### 5.4 弹窗内容

直接展示 `地图弹窗-1.png` 图片，不拆解为 React 组件。后续 task 可将图片拆解为 5 指标卡 + 列表组件。

### 5.5 层级关系

弹窗 z-index = 10，高于 SVG overlay（z=3）。弹窗 `pointerEvents: 'auto'`，内部 `stopPropagation` 防止点击弹窗取消选中。

## 8. 与时间轴历史回溯的联动（task006）

> 时间轴组件本身的 API / 视觉 / 交互设计见 [`frontend/005-timeline-history.md`](./005-timeline-history.md)。本节聚焦"地图模块作为消费者"的接入侧细节。

### 8.1 能力边界

时间轴控件是 **纯派发器**（pure dispatcher）：它**只**向 store 写入 `currentTimeIndex`，**不**感知任何 mock / 接口数据；地图模块是 **消费者**：订阅 `currentTimeIndex` 后，自己决定哪些层级、哪些数据要按时间点切换。

这种解耦的好处：timeline 可以同时服务于"地图点位回放"和"未来折线图联动"等多消费者，**timeline 不必知道有谁在订阅**。

### 8.2 数据流（全景）

```
                                ┌──────────────────────────┐
  TimelineHistory 拖动/点击  ──→ │ store.setCurrentTimeIndex│
                                └────────────┬─────────────┘
                                             │ idx
                                             ▼

                                             │
                                             ▼
              ┌──────────────────────────────┴──────────────────────────────┐
              │                                                             │
   isEffectiveLevel(currentLevel) && historyData ?           其余分支
              │                                                             │
              ▼                                                             ▼
   historyData[level][idx].markers                       (markerData.data ?? []).filter(...)
   （沿用同套 legend 过滤 + icon 规则）                   （沿用同套 legend 过滤 + icon 规则）
              │                                                             │
              └───────────→ 渲染到地图打点层（z-index=5） ←──────────────────┘
```

### 8.3 有效层级（"前三层"方案）

| 层级             | timeline 可见       | timeline 影响地图点位           | mock 数据源                          |
| ---------------- | ------------------- | ------------------------------- | ------------------------------------ |
| `city`           | ✅（service-recovery）| ✅                              | `history-timeline.json` city key     |
| `company`        | ✅                   | ✅                              | `history-timeline.json` company key  |
| `district`       | ✅                   | ✅                              | `history-timeline.json` district key |
| `street`         | ✅（仅展示，不响应）| ❌（仍走 `map-markers.json`）    | —                                    |
| `community`      | ❌                  | ❌                              | —                                    |
| `station` / `logical` | ❌              | ❌                              | —                                    |

源码约束：

-   `EFFECTIVE_LEVELS = ['city', 'company', 'district'] as const`
-   类型守卫 `isEffectiveLevel(level): level is EffectiveLevel`（在 [`map-stage.tsx`](web/pages/bj-cmcc-cmd-dispatcher/modules/map/map-stage.tsx) 内）
-   `useRequest<HistoryData>` 以 `ready: isEffective` 守卫，**仅在有效层**才 fetch，避免无谓网络请求

### 8.4 为什么不接 street 及以下？

> 用户拍板（2026-08-25）：第一版 timeline 不接 street/community/station/logical，理由：
>
> 1. L4 street 已有 `退服恢复情况.png` 折线图承载"恢复趋势"语义，与 timeline 角色重叠
> 2. L5 community 及更深的 station/logical 数据维度已经细化到"站级指标"，timeline 的"5min 粒度"已经够用，但当前 mock 数据无 PM 给出的时序基线
>
> 后续若 PM 提供 L4+ 的时序数据，可扩展 `EFFECTIVE_LEVELS`。

### 8.5 mock 数据结构（`history-timeline.json`）

```ts
interface HistoryTimePoint {
    time: string;        // HH:mm:ss
    markers: MapMarker[]; // 当前时间点该层的 marker 快照
}
interface HistoryData {
    city: HistoryTimePoint[];
    company: HistoryTimePoint[];
    district: HistoryTimePoint[];
}
```

-   24 个时间点（HH:mm:ss），每 5min 一个
-   **status 恒为 1**，时间点间通过 marker **数量增减**体现"退服→恢复"（idx 0 ~30% → idx 23 100%）
-   生成脚本：[`scripts/gen-history-timeline-mock.cjs`](.trae/skills/oss-demonstrate-project-bj-cmcc-cmd-dispatcher/scripts/gen-history-timeline-mock.cjs)
-   完整策略见 [`005-timeline-history.md §6`](./005-timeline-history.md)

### 8.6 markers useMemo 逻辑（消费者内部）

```ts
const markers = useMemo<MapMarker[]>(() => {
    if (isEffectiveLevel(currentLevel) && historyData) {
        const points = historyData[currentLevel];
        return (points?.[currentTimeIndex] ?? points?.[0])?.markers ?? [];
    }
    return (markerData?.data ?? []).filter((m) => m.type === currentLevel);
}, [currentLevel, historyData, currentTimeIndex, markerData]);
```

-   同套 `legendCheckedValues` 过滤逻辑叠加（§9），timeline 切换的 markers 也受 checkbox 影响
-   同套 `getMarkerIcon` icon 路径计算（§3.5），timeline 的资源 subType 标记享有同等渲染
-   同套 `0.15 + idx * 0.04s` 渐显延迟

### 8.7 timeline 影响资源打点

> **重要观察**：timeline 切换 markers 时，`markers[]` 内的 `subType` / `category` 字段不丢，过滤与 icon 规则完全一致。所以 timeline 拖动时，前五层的"6 类资源"打点也会按 `category` 在 filter 范围内出现/隐藏。

例：city 层 idx 0 的 markers 可能只有 3 个，全部是告警中的分公司节点（无 subType）；idx 12 出现 4 个 emergency-vehicle；idx 23 出现完整 36 个（含 4 emergency + 8 repair + 8 generator + 4 sat-bag + 4 wireless + 4 transmission + 4 分公司节点）。

## 9. 图例 Checkbox 过滤

### 9.1 概述

legend-1 层级（city~community）的图例图片上叠加 8 个 Checkbox，用于控制各类别打点的显隐。Checkbox 选中状态存储在 store（`legendCheckedValues`），`MapStage` 订阅后实时过滤打点数据。

### 9.2 数据流

```
MapLegend Checkbox 点击 → store.toggleLegendCheckbox(label)
                                ↓
map-stage 订阅 legendCheckedValues → useMemo 过滤 markers by category
                                ↓
legend-1 层级 markers 按 category 显隐
```

### 9.3 Checkbox 组件

独立封装于 `web/pages/bj-cmcc-cmd-dispatcher/components/checkbox/index.tsx`：

-   使用 UI 出图的 `checkbox.png` / `checkbox-checked.png` 作为选中态指示
-   图片路径通过 `constants.IMAGE_PATH` getter 延迟取值（运行时初始化）
-   `useMemoizedFn` 缓存点击回调
-   Props：`checked` / `onChange` / `size` / `disabled` / `style` / `value`

### 9.4 类别与位置配置

在 `presets.ts` 中以共享常量 `legendCheckboxes` 定义，所有 legend-1 层级共用：

```ts
const legendCheckboxes = [
    { label: '任务中', left: 175, top: 73 },
    { label: '空闲', left: 322, top: 73 },
    { label: '卫星便捷包', left: 175, top: 108 },
    { label: '移动油机', left: 326, top: 111 },
    { label: '抢修车辆', left: 175, top: 143 },
    { label: '应急通信车', left: 326, top: 143 },
    { label: '无线队伍', left: 178, top: 183 },
    { label: '传输队伍', left: 329, top: 183 },
];
```

-   `label`：类别名称（中文），同时作为 store 匹配 key
-   `left` / `top`：相对 legend 图片左上角的偏移（px），按设计稿调整
-   导出类型 `LegendCheckboxKey` 供类型约束

### 9.5 store 字段

| 字段                   | 类型                      | 初始值                     | 说明               |
| ---------------------- | ------------------------- | -------------------------- | ------------------ |
| `legendCheckedValues`  | `string[]`                | `['移动油机', '抢修车辆']` | 当前选中的类别列表 |
| `toggleLegendCheckbox` | `(value: string) => void` | —                          | 切换某类别选中状态 |

### 9.6 MapMarker.category

`MapMarker` 类型新增可选字段 `category?: string`，值与 checkbox 的 `label` 对应（如 `'移动油机'`）。mock 数据中 marker 带 `category` 字段时参与过滤；不带则不受 checkbox 影响。

### 9.7 markers 过滤逻辑

```ts
// legend-1 层级（city~community）按 checkbox 选中值过滤
const isLegend1Level = ['city', 'company', 'district', 'street', 'community'].includes(currentLevel);
if (isLegend1Level && legendCheckedValues.length > 0) {
    result = result.filter((m) => !m.category || legendCheckedValues.includes(m.category));
}
```

-   无 `category` 字段的 marker 始终显示（兼容现有 mock 数据）
-   `legendCheckedValues` 为空时不过滤（全部显示）

## 10. 前五层 6 类资源打点系统

> 数据层定义见 [`design/001-pm-output-data.md`](../../001-pm-output-data.md)；本节聚焦"作为前端打点的统一规则参考"。

### 10.1 为什么是 6 类？

PM §2.4 把北京移动"应急保障资源"分为 **车辆 / 物资 / 人员**三大族，每族两类：

| 族     | subType                  | 中文       | 色系         | 图标文件                        |
| ------ | ------------------------ | ---------- | ------------ | ------------------------------- |
| 车辆   | `emergency-vehicle`      | 应急通信车 | 车辆蓝 `#40A9FF` | `sub-emergency-vehicle.png`    |
| 车辆   | `repair-vehicle`         | 抢修车辆   | 车辆蓝 `#40A9FF` | `sub-repair-vehicle.png`       |
| 物资   | `generator`              | 移动油机   | 物资橙 `#FA8C16` | `sub-generator.png`            |
| 物资   | `sat-bag`                | 卫星便捷包 | 物资橙 `#FA8C16` | `sub-sat-bag.png`              |
| 人员   | `wireless-team`          | 无线队伍   | 人员青 `#13C2C2` | `sub-wireless-team.png`        |
| 人员   | `transmission-team`      | 传输队伍   | 人员青 `#13C2C2` | `sub-transmission-team.png`    |

> ⚠️ **拼写注意**：`sat-bag` 对应中文名是"卫星便捷包"（不是"便携包"），与 `presets.ts` 的 `LEGEND_CHECKBOX_LABELS` 一致。这是 mock 数据 `category` 字段必须使用的值。

### 10.2 资源打点系统全图

```
PM §2.4 资源打点清单（按"下钻收窄"作用域逐层呈现）
                │
                ▼
   ┌──── 按层级 LOD 缩放（001-pm-output-data.md §3.3） ────┐
   │   L1 全网 ~2% 缩放   │   L4 完整 100% 不缩放        │
   └──────────────────────────────────────────────────────┘
                │
                ▼
   按 001-pm-output-data.md §二 的 subType 命名生成 marker
                │
                ▼
   字段 `status` = 1（资源通常在位，不闪烁）
                │
                ▼
   写入 map-markers.json（fallback）或
   history-timeline.json[X].markers（timeline 切片）
                │
                ▼
   getMarkerIcon 根据 subType 取 sub-${subType}.png
                │
                ▼
   legendCheckedValues 过滤（仅前五层生效）
```

### 10.3 资源打点的字段约定

资源打点的 marker 必须满足以下约定，否则会被图例过滤掉或 icon 404：

| 字段        | 必需 | 取值范围                                              | 说明                                       |
| ----------- | ---- | ----------------------------------------------------- | ------------------------------------------ |
| `type`      | ✅   | `'city'` \| `'company'` \| `'district'` \| `'street'` \| `'community'` | 必须与当前层级匹配；station/logical 不允许带 subType（除 td/nr） |
| `subType`   | ✅   | 6 类资源 enum（见 §10.1）                            | 决定 `sub-${subType}.png` icon 路径         |
| `category`  | ✅   | `LEGEND_CHECKBOX_LABELS` 之一（注意"卫星便捷包"拼写） | 决定是否被 legend checkbox 过滤            |
| `status`    | ✅   | 固定 `1`（资源在位）                                  | 与节点 marker 不同；节点按 PM 状态映射      |
| `left`/`top`| ✅   | 设计稿像素坐标，绝对像素（2880×1080 系）              | 当前 mock 阶段统一为 `0` 占位               |

### 10.4 各层资源 subType 数量分布

| 层级       | emergency | repair | generator | sat-bag | wireless | transmission | 合计 | 缩放比           |
| ---------- | --------- | ------ | --------- | ------- | -------- | ------------ | ---- | ---------------- |
| L1 city    | 4         | 8      | 8         | 4       | 4        | 4            | 32   | ~2%（全网 1480） |
| L2 company | 4         | 8      | 4         | 4       | 4        | 4            | 28   | ~35%（全公司 81） |
| L3 district| 2         | 2      | 2         | 2       | 2        | 2            | 12   | 100% PM 给定      |
| L4 street  | 2         | 1      | 1         | 1       | 1        | 1            | 7    | 100% PM 给定      |
| L5 community | 1       | 1      | 1         | 1       | 1        | 1            | 6    | 100% 示意性        |
| **合计**   | **13**    | **20** | **16**    | **12**  | **12**   | **12**       | **85** | —                |

> 数量与缩放比例来自 PM §3.3；详见 [`001-pm-output-data.md` §三](../../001-pm-output-data.md)。

### 10.5 PM 缺口与 mock 处理原则

> 五个缺口统一原则：缺数据的层级按"示意图性"最小化补齐，**不臆造业务数字**；缺口标注在 `001-pm-output-data.md §3.4`，业务侧可对照补正。

| #   | 缺口                                    | L1~L5 mock 处理                                      |
| --- | --------------------------------------- | ---------------------------------------------------- |
| 1   | 移动油机按分公司拆分                     | L1 取 8 / L2 取 4                                    |
| 2   | 卫星便携包按分公司拆分                   | 同上（各 4）                                          |
| 3   | 无线/传输队伍全网总量                    | L1 按 4+4 示意                                       |
| 4   | L3 石景山抢修车/油机/队伍                | L3 按每类 2 示意                                     |
| 5   | L5 东山社区资源数量                      | L5 按每类 1 示意                                     |

### 10.6 与 station/logical subType 的关系

station / logical 层**没有** 6 类资源打点，但有节点 marker 的 subType：

| 层级       | subType 取值      | icon 文件                | 关系             |
| ---------- | ----------------- | ------------------------ | ---------------- |
| `station`  | `'td'` / `'nr'`   | `sub-td.png` / `sub-nr.png` | 物理站制式（TD 4G / NR 5G）；**无** `category`，不受 checkbox 过滤 |
| `logical`  | —（不设）         | `icon: 'radar'` 走 SVG  | 逻辑站无 subType 概念，使用雷达扩散 icon |

> **关键差异**：station 层 subType 与 6 类资源 subType **不重叠**，命名空间独立；renderer 通过 `${level}/sub-${subType}.png` 自然隔离。

### 10.7 图例过滤优先级（checkbox vs timeline）

```
markers = isEffectiveLevel ? historyData[level][idx].markers : markerData.filter(by type)
       │
       ▼
legend-1 层级（city~community）按 category 过滤：
  - category 未设 → 始终显示
  - category 已设且 legendCheckedValues 包含 → 显示
  - category 已设且不包含 → 隐藏
       │
       ▼
legend-2/3 层级（station/logical）不做 category 过滤
```
